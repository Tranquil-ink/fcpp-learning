### 先修正笔记中的两处表述

**1. `start` 和“同层去重”负责的事情不同。**

- `start` 规定下标只向右推进，消除“同一批对象按不同次序选择”造成的重复，例如先选下标0再选1，与先选1再选0。
- 同层去重消除“不同下标的相同数值”造成的等价分支，例如数组中的两个2分别作为本层第一次选择。
- 只有题目把这些结果视为同一个方案时，才应该去重。如果两件同价物品被题目视为不同对象，不能仅因价格相同就跳过。

**2. 组合中的这一句不能原样套到排列，但排列也可以排序去重。**

```cpp
if (i > start && choices[i] == choices[i - 1]) continue;
```

它用于当前的组合写法。排列可继续用你已经掌握的函数内 `duplicated`；也可在排序后使用下面的条件：

```cpp
if (i > 0 && choices[i] == choices[i - 1] && !selected[i - 1])
    continue;
```

后者需要结合 `selected` 理解，不必现在换写法。把笔记中的“此法对全排列问题不适用”改成“这句组合条件不能直接照搬到全排列”更准确。

## 模型1：按固定下标选或不选，用返回值合并分支

### 代表题：选数凑和的方案数（自拟，作为作业前置题）

第一行输入 `n M`，其中 `1≤n≤20`、`0≤M≤20000000`。第二行输入 n 个互不相同的正整数，每个不超过1000000。每个元素最多使用一次，求和恰好为 M 的子集数量。允许空集，因此 M=0 时空集也计数。

输入：

```text
3 5
2 3 5
```

输出：

```text
2
```

两种子集是 `{2,3}` 和 `{5}`。这里不区分先选2还是先选3。

### 从题意到递归函数

你的笔记用的是“枚举下一个要选的元素”。这里换一种同样基础的写法：**第 i 层只处理第 i 个元素，给它做选或不选的决定。**

定义：

> `countWays(i, remain, a)`：只能使用下标 `i…n-1` 的元素，还需要凑出 remain，能够形成多少个子集。

最初调用 `countWays(0, M, a)`。对于 `a[i]`，所有方案分成两类：

| 当前决定 | 下一次调用 | 原因 |
|---|---|---|
| 不选 `a[i]` | `countWays(i+1, remain, a)` | 待凑的和不变，当前元素不再考虑 |
| 选 `a[i]` | `countWays(i+1, remain-a[i], a)` | 还需凑的和减少，当前元素也不再考虑 |

两类方案不重叠，所以返回值相加。

### 先把出口写统一

当 `i==n`，所有元素都已经处理完：remain 为0就得到一个方案，否则得到零个方案。

这比“到最后一个元素时另写一套判断”更容易覆盖全部情况。特别是：此前已经凑够目标、最后一个元素应当不选时，也会自然进入正确的出口。

因为本题全是正数，remain 已经小于0时，后面再选任何元素都无法补救，可以直接返回0。

### 可直接运行的代码

```cpp
#include <iostream>
#include <vector>
using namespace std;

long long countWays(int i, long long remain, const vector<int>& a) {
    if (i == (int)a.size()) return remain == 0;
    if (remain < 0) return 0;

    long long ways = countWays(i + 1, remain, a);
    ways += countWays(i + 1, remain - a[i], a);
    return ways;
}

int main() {
    int n;
    long long target;
    cin >> n >> target;
    vector<int> a(n);
    for (int& x : a) cin >> x;

    cout << countWays(0, target, a) << '\n';
}
```

`return remain == 0;` 会把判断结果转换成0或1。`const vector<int>&` 表示共享读取数组，不复制，也不修改它。

### 没有 `push_back/pop_back`，为什么仍然是在枚举方案

搜索树仍然包含每个元素的两种选择，只是本题只要数量，没有必要保存具体选了哪些元素。

`i` 和 `remain` 按值传递。调用子函数时传入 `remain-a[i]`，不会修改当前调用的 remain；子函数返回后，当前调用仍可以处理另一条分支。因此不需要把 remain 加回来。

如果需要输出具体子集，再增加共享的 `path`，在选分支前加入元素、返回后删除即可。**恢复操作针对被修改的共享状态，不是每次递归后必须机械地写一次撤销。**

### 正确性、边界和复杂度

每个子集都唯一对应一串“选/不选”的决定。两条分支覆盖当前元素的全部可能，而且不能同时属于两条分支；逐层推进，所以不重不漏。到达 `i==n` 时，remain 为0恰好表示已选元素和为目标。

最坏有 `2^n` 个叶子，全部调用数为 `O(2^n)`，每次调用做常数工作，时间 `O(2^n)`。递归同时存在的深度为 `O(n)`，不是 `O(2^n)`；加上数组，空间仍为 `O(n)`。n≤20 时方案数不超过 `2^20`，代码用 `long long` 便于迁移。

手动检查：只有一个元素且正好相等、只有一个元素但不相等、答案只使用前面的元素、所有元素都要选、没有方案、M=0。

若允许负数，`remain<0` 不再是安全剪枝；若允许0，凑够目标后也可能通过再选0得到其他方案。因此“remain 为0就直接返回1”需要额外论证，不能在所有子集计数题里照搬。

### 同一棵搜索树，题目要求不同，返回值就不同

| 要求 | 返回或记录什么 | 如何合并分支 |
|---|---|---|
| 是否存在 | `bool` | 两条分支取逻辑或；发现一个可行方案即可停止继续寻找 |
| 方案总数 | 整数 | 两条分支相加；找到一个方案仍需继续统计 |
| 输出所有方案 | 当前路径和结果容器，或直接输出 | 每个成功出口记录一次；维护并恢复路径 |

求存在性时，不宜为了输出 YES/NO 而先把全部方案数算出来：会做更多工作，方案数还可能超过整数范围。

## 模型2：下一次选择不小于上一次，生成无序分解

### 代表题：作业《分解因数》

第三阶段练习（2）第6题。[原题](https://programming.pku.edu.cn/probset/ad843b8196f44103a210e5c359afb74e/3f6250de057749ef9db19293503ca093/)

把整数 a 分解成若干个大于1的整数的乘积，要求因数非递减：

\[
a=a_1a_2\cdots a_k,\qquad 1<a_1\le a_2\le\cdots\le a_k.
\]

求不同分解的数量，`a=a` 也算一种。输入第一行是测试组数，之后每组一行 a，`1<a<32768`；每组输出一行分解数。

例如20有四种：`20`、`2×10`、`4×5`、`2×2×5`。

### 为什么需要一个“下限”参数

如果每一层都从2重新枚举，就会同时得到 `2×10` 和 `10×2`。我们给每个无序分解约定唯一的书写顺序：因数从小到大排列。

定义：

> `countFactor(remain, low)`：把 remain 分解为若干个因数，后续每个因数都至少为 low，有多少种合法分解。

最初调用 `countFactor(a, 2)`。枚举当前因数 d：只有 d 整除 remain 才能选；选完后剩下 `remain/d`，下一因数仍可等于 d，因此调用 `countFactor(remain/d, d)`。

这与你笔记中的组合枚举相通：那里传递起始下标，这里传递下一个因数允许的最小值。候选因数不是一个给定数组，而是现场枚举出来的。

### 用统一的成功出口，先写容易核对的版本

当 remain=1，说明原数已经被之前选出的因数除尽，完成一种分解，返回1。

没有合法因数时，循环不会产生成功分支，返回0。例如 `countFactor(3,4)`：剩余的3不能继续使用，因为它小于下限4。

### 可直接运行的代码

```cpp
#include <iostream>
using namespace std;

long long countFactor(int remain, int low) {
    if (remain == 1) return 1;

    long long ways = 0;
    for (int d = low; d <= remain; ++d) {
        if (remain % d != 0) continue;
        ways += countFactor(remain / d, d);
    }
    return ways;
}

int main() {
    int tests;
    cin >> tests;
    while (tests--) {
        int a;
        cin >> a;
        cout << countFactor(a, 2) << '\n';
    }
}
```

这个版本故意保留直接的循环与出口，不先把“最后一个因数”改写成特殊计数技巧。数 a 本身也在首层枚举范围内，因此 `a=a` 会走到 `countFactor(1,a)`，不会漏掉。

注意不能把循环终点直接改为 `sqrt(remain)`：那样会漏掉以 remain 自身结束的分支。若以后优化到平方根，需要重新安排最后一个因数的处理；当前先独立写对上面的版本。

### 不重不漏的理由

任意合法分解已经按非递减顺序排列。第一层能枚举它的第一个因数，之后每层的下限就是刚选的因数，所以后续因数仍然符合下限，最终一定到达 remain=1。

反过来，每条成功路径的因数乘积都是 a，且因数非递减。同一个分解只有一种非递减顺序，因此不会因选择次序不同而重复。

这里的 `low` 在本题不仅是加速条件，也是在定义唯一的生成顺序。因数允许重复，所以传 d；传 `d+1` 会错误地禁止 `2×2×5`。

### 边界和复杂度

每选一个因数，remain 至少减半，递归深度不超过 `floor(log2 a)`。输入 a>1，最初不会把空分解算成答案。质数应只有自身一种分解；平方数与二的幂适合检查相同因数是否允许重复。

时间不能只按递归深度计算。本实现的总工作量是各次调用的候选扫描长度之和。若记调用数为 V，可给出宽松上界 `O(aV)`；更具体地，每个非终止调用扫描 `max(0, remain-low+1)` 个候选。额外空间为 `O(log a)`。这是按题目小数值范围采用的直接搜索，不适合把 a 换成极大的整数后原样使用。

## 模型3：一行最多放一个，但并不要求每行都放

### 代表题：作业《棋盘问题》

第三阶段练习（2）第4题。[原题](https://programming.pku.edu.cn/probset/ad843b8196f44103a210e5c359afb74e/e201d4c7a17f4b6a971fa98bad77321a/)

在 n×n 的不规则棋盘上放 k 个相同棋子，任何两个不能同行或同列。`#` 能放，`.` 不能放。输入多组，每组先输入 `n k`，再输入 n 行棋盘；`n≤8`、`k≤n`，读到 `-1 -1` 结束。每组输出方案数，原题保证答案小于 `2^31`。

样例：

```text
2 1
#.
.#
4 4
...#
..#.
.#..
#...
-1 -1
```

输出：

```text
2
1
```

### 为什么不能直接套 N 皇后

N 皇后要求每行恰好放一个。这里可能 k<n，因此某些行必须空着。仍然按行处理，但每层增加一种选择：**当前行不放棋子。**

定义：

> `countBoard(row, left)`：前 row 行已经决定完成，当前列占用情况保存在 usedCol 中；还要在 `row…n-1` 行放 left 个棋子，有多少种方法。

函数含义包括共享的 usedCol，不能认为只有两个整数参数就描述了全部状态。

每层只有两类决定：不放，进入下一行；或者选一个合法且未被占用的列放一颗，进入下一行并让 left 减1。

### 两个数量边界

1. `left==0`：已经放够，剩下的行全部不放只有一种完成方式，返回1。
2. `n-row<left`：剩余行数比还需放的棋子少，每行最多一颗，因此不可能完成，返回0。

这里剩余行数包含当前行，所以是 `n-row`。等号不能剪：剩余行数刚好足够时，仍可能每行放一颗。

### 可直接运行的代码

```cpp
#include <iostream>
#include <vector>
#include <string>
using namespace std;

int n;
vector<string> board;
vector<bool> usedCol;

long long countBoard(int row, int left) {
    if (left == 0) return 1;
    if (row == n || n - row < left) return 0;

    // 当前行不放。
    long long ways = countBoard(row + 1, left);

    // 当前行放一个，枚举放在哪一列。
    for (int col = 0; col < n; ++col) {
        if (board[row][col] != '#' || usedCol[col]) continue;
        usedCol[col] = true;
        ways += countBoard(row + 1, left - 1);
        usedCol[col] = false;
    }
    return ways;
}

int main() {
    int k;
    while (cin >> n >> k) {
        if (n == -1 && k == -1) break;
        board.resize(n);
        for (string& row : board) cin >> row;
        usedCol.assign(n, false);
        cout << countBoard(0, k) << '\n';
    }
}
```

### 这次为什么要恢复标记

usedCol 表示**当前这一个摆放方案**已经用了哪些列。某列在“当前行放这里”的分支里被占用，返回后换一个位置尝试时，该占用也必须取消。

它与阶段2统计连通块时的 vis 含义不同：连通块的 vis 表示该格已被本次完整遍历处理，不会因换一条探索路线而重新变成未处理。

row、left 按值传递，所以不需要在返回后减 row、加 left。棋盘没有改动，也不用恢复棋盘字符。

### 正确性、边界和复杂度

任意合法摆法，在当前行要么没有棋子，要么恰好有一颗。这两类被代码完整覆盖；行号严格递增，同行冲突自动被排除；列标记排除同列冲突。每个摆法按行展开只有一条搜索路径，所以相同棋子不会因放置先后不同被重复计数。

搜索深度至多 n，每层最多有“不放”和 n 个放置选择，可给出 `O((n+1)^n)` 的粗略时间上界；列冲突和数量剪枝会减少分支。n≤8 是可以采用这种枚举的重要条件。额外搜索空间 `O(n)`，包含输入棋盘的总空间 `O(n²)`。

手动检查：k=1、k=n、可用位置全挤在同一列、位置足够但同行/同列冲突、只有反对角线能放、多组输入。原题 k 是正整数；这段代码也自然支持 k=0，并返回空摆法1种。

### 练习：先不给答案

## 模型4：把切分位置当成选择，恰好分成指定数量的连续段

### 代表题：作业《插入乘号》

第三阶段练习（4）第2题。[原题](https://programming.pku.edu.cn/probset/e91cfb239dde47c1a97f5ad774f3b208/c470ae98adb84c4a94885711e1a770b1/)

输入非负整数 s 和乘号数量 k，`s≤10^9`、`0≤k<s的位数`。在数字之间插入恰好 k 个乘号，使乘积最大。每段非空，不能重排数字。原题保证相关乘法不会使 int 溢出。

输入 `12345 2`，输出 `2460`，对应 `123×4×5`。

把乘号放在哪里，等价于把数字串切成 `k+1` 个非空连续段。某一段的前导0按十进制数值解释，例如 `05` 的值为5。

### 定义本次调用负责什么

> `searchCuts(pos, pieces, product)`：`[0,pos)` 已经分好，所有已完成数段的乘积为 product；把从 pos 开始的剩余数字切成恰好 pieces 段，尝试更新最大答案。

初始调用 `searchCuts(0, k+1, 1)`。初始乘积为1，因为还没有乘入任何数段。

若只剩一段，它只能是整个剩余后缀；此时读取这个后缀、乘入 product，就得到了一个完整方案。

否则枚举下一段的终点 end：当前段为 `s[pos…end]`，后续从 `end+1` 开始，还需 `pieces-1` 段。

### 下一段最多延伸到哪里

剩余字符数为 `L-pos`，少于 pieces 时无法切分。选完当前段，还需给后面的每段至少留一个字符：

\[
L-(end+1)\ge pieces-1,
\]

所以 `end≤L-pieces`。这个范围来自“留下的字符必须够分”，不是凭经验写出来的循环边界。

### 可直接运行的代码

```cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

string digits;
int lengthOfDigits;
long long best = 0;

void searchCuts(int pos, int pieces, long long product) {
    if (lengthOfDigits - pos < pieces) return;

    if (pieces == 1) {
        long long value = 0;
        for (int i = pos; i < lengthOfDigits; ++i)
            value = value * 10 + (digits[i] - '0');
        best = max(best, product * value);
        return;
    }

    long long value = 0;
    for (int end = pos; end <= lengthOfDigits - pieces; ++end) {
        value = value * 10 + (digits[end] - '0');
        searchCuts(end + 1, pieces - 1, product * value);
    }
}

int main() {
    int k;
    cin >> digits >> k;
    lengthOfDigits = (int)digits.size();
    searchCuts(0, k + 1, 1);
    cout << best << '\n';
}
```

这里把输入当字符串保存，便于按数字位置切分。循环中的 value 依次成为当前起点开始的一位数、两位数、三位数，不必每次重新 `substr` 后转换。

value 是当前函数自己的局部变量，递归调用不会修改它。循环返回后继续扩展同一个前缀，是有意保留 value，**不应把它恢复成0**。product 按值传递，也不需要撤销乘法。

### 正确性、边界和复杂度

每个合法切法唯一对应一串递增的段终点。第一层枚举第一段终点，后续逐段枚举，最后一段取完整后缀，因此覆盖全部合法切法且不重复。数量剪枝只排除字符不足以分成所需段数的情况。每个完整方案计算一次乘积，最大值就是答案。

L位数字有 L-1 个可切间隙，完整切法数为 `C(L-1,k)`。考虑搜索中的部分方案及末段解析，可以使用 `O(L·2^L)` 的保守时间上界，额外空间 `O(L)`。这里 L≤10，因此无需先学 DP 就能完成原题。

检查：k=0、k=L-1、数字中有0、s=0且k=0、最佳切法靠近开头或结尾。本题所有乘积非负，best 初始化为0正确；换成可能产生负答案的题目时，不能默认使用0初始化。

## 模型5：维护累计量，搜索最优值，并剪去不可能更优的分支

### 代表题：作业《平衡矩阵》

第三阶段练习（3）第9题。[原题](https://programming.pku.edu.cn/probset/c5ba205300e44fdaaed12966863276fc/c3d6dc32ad4f4f6fa37a2a82a96f334f/)

输入多组数据。每组输入 n 和 n×n 正整数矩阵，`1≤n≤7`，元素不超过10000；读到 n=-1 结束。每行可以独立循环左移任意次，使最终各列和中的最大值尽量小，输出这个最小值。

例如矩阵：

```text
4 6
3 7
```

第一行不移、第二行左移一次后，两列和为11与9，最大值为11，这是最优值。

### 先把无限次移动变成有限选择

长度为 n 的一行左移 n 次就回到原样。因此每行只需枚举左移 `0…n-1` 格。

左移 shift 后，目标列 col 上的值来自原列 `(col+shift)%n`。例如 `[4,6]` 左移1格，目标第0列来自原第1列，即6。

### 当前状态只维护已经处理的行

定义：

> `searchRow(row)`：前 row 行的移位方式已经确定；colSum 保存这些行形成的各列部分和，继续决定剩余行，并尝试降低 best。

一层决定一行的 shift。每次尝试：把该行旋转后的值加进 colSum，递归处理下一行，再逐列减掉，恢复到尝试前。

不必真的搬动矩阵。原矩阵一直保留，更新的只是列和数组，这样恢复操作更容易检查。

### 如何判断一条分支已经没有希望

先用“所有行都不左移”的完整方案初始化 best，它一定是一个可实现的答案。

假设目前部分列和最大值为 currentMax。由于后面的矩阵元素全为正数，继续加入剩余行后，每一列的和都不会降低，最终最大列和至少为 currentMax。

因此若 `currentMax>=best`，这条分支不可能得到严格更小的值，可以停止。这里比较的是**部分方案的下界**与**已找到的完整方案的值**，不是把部分方案直接当成答案。

### 可直接运行的代码

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int n;
vector<vector<int>> a;
vector<int> colSum;
int best;

void searchRow(int row) {
    int currentMax = *max_element(colSum.begin(), colSum.end());
    if (row == n) {
        best = min(best, currentMax);
        return;
    }
    if (currentMax >= best) return;

    for (int shift = 0; shift < n; ++shift) {
        for (int col = 0; col < n; ++col)
            colSum[col] += a[row][(col + shift) % n];

        searchRow(row + 1);

        for (int col = 0; col < n; ++col)
            colSum[col] -= a[row][(col + shift) % n];
    }
}

int main() {
    while (cin >> n && n != -1) {
        a.assign(n, vector<int>(n));
        vector<int> initialSum(n, 0);
        for (int row = 0; row < n; ++row) {
            for (int col = 0; col < n; ++col) {
                cin >> a[row][col];
                initialSum[col] += a[row][col];
            }
        }

        best = *max_element(initialSum.begin(), initialSum.end());
        colSum.assign(n, 0);
        searchRow(0);
        cout << best << '\n';
    }
}
```

`max_element` 返回最大元素的位置，前面的 `*` 取出该位置的值。n至少为1，所以这里不会对空数组取最大值。

### 不重不漏与剪枝正确性

不考虑剪枝，每一行的 n 种移位都会被枚举，一条根到叶的路径对应一个完整移位方案，所以所有可行结果都会被覆盖。若一行本身有周期，不同 shift 可能产生相同的一行；这里只求最优值，重复检查不会影响答案。

剪枝时，该分支的任何完整结果都至少为 currentMax，而已有可行答案 best 不大于它，所以该分支不可能改善答案。即使剪掉了一些与当前答案相同的方案，最优值仍然保留。

如果改成“还要统计所有最优方案数”，这个等号就需要重新考虑。如果矩阵允许负数，后续行可能降低列和，当前剪枝依据也会失效。这两个条件改变后，不能原样复用剪枝。

### 边界和复杂度

不剪枝时有 `n^n` 个完整移位选择，更新或计算状态需要 `O(n)`，总时间上界 `O(n^(n+1))`；n=7 时有 `7^7=823543` 个完整选择，原范围适合直接搜索。剪枝加快实际运行，不改变这里的最坏上界。

递归深度 `O(n)`，列和 `O(n)`；包含输入矩阵总空间 `O(n²)`。每列和不超过70000，用 int 足够。

检查：n=1、每行各元素相同、初始状态已经最优、某行存在重复值、多组数据。每次递归返回后，colSum 必须与进入该次 shift 尝试前完全相同。

## 把几种“标记”和“剪枝”区分开

| 写法或变量 | 准确含义 | 返回上层后怎么办 |
|---|---|---|
| 图遍历中的 vis | 本次遍历是否已经发现该节点 | 通常保留，避免重复处理 |
| 排列中的 selected | 该下标是否已经在当前排列中使用 | 恢复，让其他方案也能选它 |
| 本层 duplicated | 本次调用的同层分支是否已试过这个值 | 保留到本层结束；不会跨递归层共享 |
| 棋盘 usedCol | 当前摆法已占用的列 | 恢复 |
| 路径搜索中的 inPath | 当前这条路径是否已经经过该格 | 枚举不同路径时要恢复 |
| 参数 remain、left、product | 当前调用的局部数值状态 | 按值传递时不用手动恢复 |

例如图中有两条路径 `s→a→c→t` 与 `s→b→c→t`。只问 t 能不能到达时，发现 c 后可以保留访问标记；若要枚举所有不重复经过节点的路径，第一条路径用过 c，不代表第二条路径不能再用 c。此时限制的是“同一条路径内不能重复”，而不是“全部搜索过程只能访问一次”。

再把本讲的剪枝分成三类：

- **排除不合法选择**：因数必须整除剩余数；棋子不能占用已使用列。
- **排除已不可能完成的部分方案**：剩余行数不足、字符不足、正数凑和已经超过目标。
- **排除不可能改善答案的分支**：平衡矩阵中部分最大列和已经不小于 best。这里只求最优值时可这样剪，计数题需另核对等号。

非递减因数、组合的递增下标还在消除等价生成顺序。不要把所有条件都只当成“加速”：有些约束是在保证方案不重复。

5. 最后独立实现《平衡矩阵》。先保留状态恢复、去掉最优值剪枝，核对小数据；再加入剪枝，验证答案一致。之后按需要做5A或5B。
6. 隐去模型名称完成两道混合题；隔两三天重写一次棋盘或平衡矩阵，检查是否能从函数含义重新推导代码。

不要求一次刷完全部练习。每个模型先完成代表题与一题迁移，能独立写出且解释边界后再加变式；模型5作为综合训练，不必为了把所有计数变式做完而一直停留在阶段3。

离开本阶段前，应能用自己的代码说明：

- 一层究竟决定哪个对象，为什么每个合法方案只被生成一次。
- 成功出口和失败出口分别是什么；为什么用 `i==n`、`row==n` 能自然覆盖最后一步。
- 题目要存在性、方案数还是最优值，为什么不能随便提前返回。
- 每个共享变量修改前后代表什么，返回后要恢复到哪个时刻。
- 剪枝依赖了哪些条件；如果允许0、负数、重复值，哪些判断需要重新审视。
- 能按搜索分支估算总规模，并区分递归深度与总调用次数。
