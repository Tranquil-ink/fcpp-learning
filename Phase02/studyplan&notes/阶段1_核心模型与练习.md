**一、模型 ①：本次处理一点，剩下的交给更小的问题**

代表题：输入一个只含小写字母的非空字符串，长度不超过 100，判断它是不是回文，输出 `true` 或 `false`。

例如，`abccba` 是回文，`abca` 不是。

**1．先准确说清函数负责什么**

定义：

```cpp
bool isPalindrome(const string& s, int l, int r);
```

它的含义是：

> 返回字符串闭区间 `s[l..r]` 是否为回文。

这里必须明确是**闭区间**：两端字符都属于本次问题。

考虑 `abccba`：

- 本次检查最外面的两个字符是不是相同。
- 如果不同，整个区间立即失败。
- 如果相同，剩下的任务就是判断内部的 `bccb`。

因此：

\[
P(l,r)=
\begin{cases}
\text{true},&l\ge r,\\
\text{false},&s_l\ne s_r,\\
P(l+1,r-1),&s_l=s_r.
\end{cases}
\]

**2．为什么出口是 `l >= r`？**

两种结束情况都要覆盖：

| 情况 | 含义 | 结论 |
|---|---|---|
| `l == r` | 只剩一个字符 | 是回文 |
| `l > r` | 已经检查完，剩下空区间 | 是回文 |

这正好对应奇数长度和偶数长度。

以 `abccba` 为例：

```text
P(0,5) → P(1,4) → P(2,3) → P(3,2)
```

最后一次调用不能再访问 `s[l]`、`s[r]`，应该直接返回。

**你之前容易卡住的边界问题，在这里可以通过函数定义解决：空区间也有明确答案，就不必在上一层为“最后一对字符”额外写特殊分支。**

**3．实现**

```cpp
#include <iostream>
#include <string>
using namespace std;

bool isPalindrome(const string& s, int l, int r) {
    if (l >= r) return true;

    if (s[l] != s[r]) return false;

    return isPalindrome(s, l + 1, r - 1);
}

int main() {
    string s;
    cin >> s;

    cout << (isPalindrome(s, 0, (int)s.size() - 1)
                 ? "true" : "false");
}
```

`const string&` 表示所有调用都读取同一个字符串，不会在每层复制一遍字符串。

注意这句：

```cpp
return isPalindrome(s, l + 1, r - 1);
```

内部区间的答案就是本次调用的答案，所以必须把它返回。仅仅调用函数，不等于已经返回它的结果。

**4．正确性与复杂度**

每次确认最外面一对字符相等，再交给内部区间；最终所有对称位置都检查过，或者遇到一处不同而失败。

- 最坏时间：\(O(n)\)。
- 最大递归深度：\(O(n)\)。
- 调用栈空间：\(O(n)\)。

这里每次只有一个递归调用，形成一条调用链。

**二、模型 ②：把全部情况分成几类，答案等于各类答案之和**

代表题：作业[《拔牙》](https://programming.pku.edu.cn/probset/ad843b8196f44103a210e5c359afb74e/c48f72153bac4f068373b92e78d12261/)。

有 \(n\) 颗牙，每个月拔 1 颗或 2 颗，直到全部拔完。问不同的拔牙顺序有多少种。原题范围为 \(0<n<30\)。

例如，3 颗牙有：

\[
1+1+1,\quad 1+2,\quad 2+1.
\]

顺序不同算不同方案。

**1．函数统计什么？**

定义：

```cpp
long long ways(int n);
```

含义是：

> 还剩 `n` 颗牙时，后续完整拔完的方案数。

这里统计的是**从现在开始的后续方案**，所以不需要记录前面几个月已经怎么拔。

**2．按第一个月的操作分类**

任何方案，第一个月只能：

- 拔 1 颗，后面剩 `n-1` 颗，有 `ways(n-1)` 种。
- 拔 2 颗，后面剩 `n-2` 颗，有 `ways(n-2)` 种。

这两类：

- 覆盖了全部方案；
- 不会重叠，因为第一个月拔的数量不同。

于是：

\[
W(n)=W(n-1)+W(n-2).
\]

**计数题里最值得检查的是：你划分的几类，是否不重不漏。** “出现两个递归调用”只是代码形式，分类理由才是核心。

**3．为什么 `ways(0) = 1`？**

剩 0 颗表示已经顺利完成。后续只有一种安排：不再操作。

这不是说“0 颗牙也要拔一次”，而是：

> 一个已经完成的方案，应贡献 1 次计数。

另外，剩 1 颗时，只有拔 1 颗这一种方案。

所以：

\[
W(0)=1,\qquad W(1)=1.
\]

计算过程例如：

\[
\begin{aligned}
W(2)&=W(1)+W(0)=2,\\
W(3)&=W(2)+W(1)=3,\\
W(4)&=W(3)+W(2)=5.
\end{aligned}
\]

**4．实现**

```cpp
#include <iostream>
using namespace std;

long long ways(int n) {
    if (n == 0 || n == 1) return 1;

    long long a = ways(n - 1);
    long long b = ways(n - 2);

    return a + b;
}

int main() {
    int n;
    cin >> n;
    cout << ways(n);
}
```

把两个返回值分别保存，方便你用断点观察：

1. 先进入 `ways(n-1)`。
2. 它全部算完并返回后，结果保存在本层的 `a`。
3. 再计算 `ways(n-2)`。
4. 本层把两个结果相加并返回。

**每层都有自己的 `n`、`a`、`b`。** 子调用里的同名变量不会把上一层变量覆盖掉。

**5．为什么递归深度不等于运行次数？**

最深的一条链大约是：

```text
ways(n) → ways(n-1) → … → ways(1)
```

深度只有 \(O(n)\)。

但是 `ways(n-2)` 既会直接被本层调用，也会出现在 `ways(n-1)` 的内部，存在大量重复计算。

- 时间是指数级，可用 \(O(2^n)\) 作上界。
- 调用栈空间是 \(O(n)\)，因为已经返回的分支不会一直占着栈。

原题 \(n<30\)，可以用它练朴素递归；以后进入阶段 4，再解决重复计算问题。现在先把函数含义与分类依据练清楚。

- 不同的步长顺序算不同方案。

**三、模型 ③：输入本身有左右子结构，分别处理后合并**

代表题：求二叉树高度。

约定：

- 空树高度为 0。
- 只有根节点的树，高度为 1。
- 高度按最长路径上的**节点数**计算。

输入：

- 第一行是节点数 `n` 和根编号 `root`，\(1\le n\le1000\)。
- 接下来 `n` 行，第 `i` 行给出节点 `i` 的左右孩子编号。
- `0` 表示没有这个孩子。
- 输入保证是一棵合法二叉树，所有节点都属于这棵树。

例如：

```text
4 1
2 3
0 4
0 0
0 0
```

表示节点 1 的孩子是 2、3；节点 2 只有右孩子 4。这棵树高度为 3。

**1．函数负责什么？**

```cpp
int height(int u);
```

含义是：

> 返回以节点 `u` 为根的子树高度。

本次调用不用关心自己在整棵树的第几层，只负责求“自己这棵子树”的高度。

**2．先假设子调用能完成它的任务**

如果：

```cpp
height(L[u])
```

能求出左子树高度，而：

```cpp
height(R[u])
```

能求出右子树高度，那么本次答案就是：

\[
H(u)=1+\max(H(L_u),H(R_u)).
\]

多出来的 1 是当前根节点。

出口是：

\[
H(0)=0.
\]

这样叶子节点自然得到：

\[
1+\max(0,0)=1,
\]

不需要单独写“如果左右孩子都不存在”。

**3．实现**

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

vector<int> L, R;

int height(int u) {
    if (u == 0) return 0;

    int leftHeight = height(L[u]);
    int rightHeight = height(R[u]);

    return 1 + max(leftHeight, rightHeight);
}

int main() {
    int n, root;
    cin >> n >> root;

    L.resize(n + 1);
    R.resize(n + 1);

    for (int i = 1; i <= n; ++i) {
        cin >> L[i] >> R[i];
    }

    cout << height(root);
}
```

这里 `L`、`R` 是所有调用共享的树结构，递归期间只读取；`leftHeight`、`rightHeight` 则是每层独立的局部变量。

**4．理解“先调用”和“先得到答案”**

示例中，节点 1 最先被调用，但它必须等待节点 2、3 的答案，才能求出自己的高度。

沿左侧进入时：

```text
height(1) → height(2) → height(0)
```

`height(0)` 返回后，还会继续求节点 2 的右子树。**一次子调用返回，只代表这一项任务结束，不代表父调用结束。**

这也是理解归并排序调用过程的关键。

**5．遍历顺序与这里有什么关系？**

对一个节点，总共有三个放置“处理当前节点”的位置：

```cpp
处理当前节点;       // 前序位置
递归处理左子树;
处理当前节点;       // 中序位置
递归处理右子树;
处理当前节点;       // 后序位置
```

实际程序根据需求选择其中一个位置。

求高度必须在左右子树答案都拿到后计算，因此属于“子问题先完成，再处理当前节点”的顺序。

- 时间：\(O(n)\)，每个节点处理一次。
- 栈空间：\(O(h)\)，其中 \(h\) 是树高。
- 极端情况下树退化成一条链，空间为 \(O(n)\)，不能一概写成 \(O(\log n)\)。

**练习 3A：每棵子树有多少个节点（自编同类题）**

沿用母题的输入格式。

- 按编号 `1..n` 输出，每行一个整数。
- \(1\le n\le1000\)。

**四、模型 ④：按区间规则分治，并生成输出**

代表题：**黑白图像编码，自编题**。

有一张 \(N\times N\) 黑白图像：

- `0` 表示白色，`1` 表示黑色。
- \(N=2^k\)，\(0\le k\le5\)。

对一个正方形区域：

1. 如果全是 `0`，输出 `0`。
2. 如果全是 `1`，输出 `1`。
3. 否则，先输出 `Q`，再把它平分成四个正方形，依次编码：
   **左上、右上、左下、右下**。

输入 `N`，再输入 `N` 行图像。输出整张图像的编码。

例如：

```text
2
01
11
```

编码是：

```text
Q0111
```

**1．用什么参数表示一个子问题？**

不必把子图复制出来。

定义：

```cpp
void encode(int r, int c, int len);
```

含义是：

> 输出左上角为 `(r,c)`、边长为 `len` 的正方形区域的完整编码。

它覆盖：

- 行：`r` 到 `r + len - 1`；
- 列：`c` 到 `c + len - 1`。

这里函数的任务是**产生输出**，所以不需要返回编码字符串。

**2．出口由题目规则决定**

本题不一定拆到单个格子才停。

只要当前区域颜色相同，就可以直接输出一个字符并结束。例如，一个全白的 \(16\times16\) 区域，也应该立刻输出 `0`。

单个格子当然一定同色，因此 `len == 1` 自然包含在这个出口中。

**3．分成哪四个子问题？**

设：

```cpp
int half = len / 2;
```

四个子区域分别是：

| 子区域 | 左上角 | 边长 |
|---|---|---|
| 左上 | `(r, c)` | `half` |
| 右上 | `(r, c + half)` | `half` |
| 左下 | `(r + half, c)` | `half` |
| 右下 | `(r + half, c + half)` | `half` |

本层只负责判断是否同色，以及安排这四次调用。每个子调用负责完整输出自己的区域。

**4．实现**

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

vector<string> image;

void encode(int r, int c, int len) {
    char color = image[r][c];
    bool same = true;

    for (int i = r; i < r + len; ++i) {
        for (int j = c; j < c + len; ++j) {
            if (image[i][j] != color) {
                same = false;
            }
        }
    }

    if (same) {
        cout << color;
        return;
    }

    cout << 'Q';

    int half = len / 2;
    encode(r, c, half);
    encode(r, c + half, half);
    encode(r + half, c, half);
    encode(r + half, c + half, half);
}

int main() {
    int n;
    cin >> n;

    image.resize(n);
    for (string& row : image) {
        cin >> row;
    }

    encode(0, 0, n);
}
```

**5．输出顺序如何随着调用展开？**

考虑：

```text
4
0011
0011
0100
1000
```

整张图不均匀，先输出 `Q`。四块分别是：

- 左上全白：输出 `0`。
- 右上全黑：输出 `1`。
- 左下混合：输出它自己的完整编码 `Q0110`。
- 右下全白：输出 `0`。

因此：

```text
Q + 0 + 1 + Q0110 + 0
```

拼起来得到：

```text
Q01Q01100
```

**父调用不用知道左下子图会输出几个字符，只需等待它完整结束，再处理右下子图。**

如果把 `cout << 'Q'` 移到四次递归之后，输出就改变了。输出语句的位置是算法的一部分。

**6．复杂度与适用边界**

最坏情况下，每一层合计检查 \(N^2\) 个格子，共约 \(\log N\) 层：

- 时间：\(O(N^2\log N)\)。
- 调用栈空间：\(O(\log N)\)，不计输入图像。

这也说明：**分治不一定是 \(O(n\log n)\)，要看每层总工作量。**

本题保证边长是 2 的幂，才能持续等分。如果允许任意边长，就必须重新定义怎么拆，不能直接照搬。

定义一个区间的编码：

其中《角谷猜想》还有一个思维上的细节：**递归能够结束，不一定表现为每一步的数值都减小。** 本题的奇数步骤会增大数值；不能把“样例最终到 1”当成对所有正整数都终止的数学证明。做编程训练时，可以先用小输入观察调用与输出。

暂缓这些作业：

- **分解因数、棋盘问题、八皇后、集合里的乘法**：留到阶段 3，重点是选择约束、去重或回溯。
- **子集合划分**：需要额外建立计数模型，现在不作为递归入门题。
- **不相邻元素最大和、钢条切割、石子归并**：按后面的 DP 阶段学习。
- **计算勒让德多项式**：属于可衔接的数值递推，但仓库中的关键公式是图片；做题前要查看原公式，不能只凭题名套公式。

**建议先完成的顺序是：1A → 独立重写《拔牙》→ 2A → 3A → 4A。** 再用 1B、2B、3B 和归并排序检查迁移能力。

每题动手前只写三句话：

> **本次调用负责什么？最小情况直接返回什么？子调用完成后，本层还要做什么？**

最后专门做一次边界检查：把模型 ① 的出口临时改成 `l == r`，用长度为 2 的回文追踪调用，找出第一次访问无效位置发生在哪里。能解释这个错误，比仅仅记住 `l >= r` 更有用。
