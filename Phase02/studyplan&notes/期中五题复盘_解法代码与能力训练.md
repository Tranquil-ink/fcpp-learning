## 1. 缓存命中率：把小数问题转成整数问题

### 1.1 题意与必须遵守的规则

给定命中次数 `x` 和访问总次数 `y`，百分数的数值是

$$p=\frac{100x}{y}.$$

- 如果 `x == y`，输出 `100%`。
- 否则先将 **原始的** `p` 四舍五入到整数。
- 如果仍显示为 `100%`，改为保留一位小数，再不行就保留两位，依次增加。
- 输出第一次不再等于 `100.0…0%` 的结果。
- **每次都从原始比例重新计算**，不能从上一次已舍入的结果继续计算。

数据范围：`1 ≤ T ≤ 10`，`1 ≤ x ≤ y ≤ 1,000,000`。输入顺序是 **x、y**。

例如 `x=999, y=1000`，真实比例为 `99.9%`。保留整数会变成 `100%`，因此改用一位小数，输出 `99.9%`。

### 1.2 核心转换：用整数 r 表示保留 k 位后的结果

设保留 `k` 位小数，令

$$s=10^k.$$

先把百分数放大 `s` 倍，再四舍五入成整数：

$$r=\left\lfloor\frac{100xs}{y}+\frac12\right\rfloor
  =\left\lfloor\frac{200xs+y}{2y}\right\rfloor.$$

所有数都非负，所以 C++ 的整数除法正好实现这里的向下取整：

```cpp
long long r = (200LL * x * scale + y) / (2LL * y);
```

这一步同时解决了两件事：不依赖浮点数判断临界值，也不需要先构造字符串再判断它是不是 `100.000%`。

| 变量 | 准确含义 |
|---|---|
| `k` | 当前尝试保留的小数位数 |
| `scale` | `10^k` |
| `r` | 原始百分数乘以 `scale` 后四舍五入得到的整数 |
| `r / scale` | 要输出的整数部分 |
| `r % scale` | 要输出的小数部分，需补足 `k` 位 |

此时，显示成 `100.0…0%` 的充要条件就是：

```cpp
r == 100LL * scale
```

否则即可输出。

### 1.3 为什么小数部分要补零？

一般地，如果 `k=3`、`r=12005`，它表示的是 `12.005`。直接输出余数 `5` 会错误地得到 `12.5`。

```cpp
cout << '.' << setfill('0') << setw(k) << r % scale;
```

`setw(k)` 规定下一项的最小宽度，`setfill('0')` 用 0 填充。`setw` 只影响紧随其后的这一项。

### 1.4 为什么循环会结束？为什么 long long 足够？

当 `x<y` 时，距离 100 的差至少是

$$100-p=\frac{100(y-x)}{y}\ge\frac{100}{10^6}=10^{-4}.$$

保留四位小数时，能被舍入为 100 的距离至多为半个末位单位，即 `0.00005`。上式保证实际差距更大，所以**最迟在 k=4 时一定结束**。

最坏的例子是 `999999/1000000`：

| 保留位数 k | 舍入后的显示 | 是否结束 |
|---|---|---|
| 0 | `100%` | 否 |
| 1 | `100.0%` | 否 |
| 2 | `100.00%` | 否 |
| 3 | `100.000%` | 否 |
| 4 | `99.9999%` | 是 |

最大中间乘积约为 `200 × 10^6 × 10^4 = 2 × 10^12`，会超过 `int`，但在 `long long` 范围内。

### 1.5 最终代码

```cpp
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    int T;
    cin >> T;
    while (T--) {
        long long x, y;
        cin >> x >> y;
        if (x == y) {
            cout << "100%\n";
            continue;
        }

        int k = 0;
        long long scale = 1;  // scale = 10^k
        while (true) {
            long long r = (200LL * x * scale + y) / (2LL * y);
            if (r != 100LL * scale) {
                cout << r / scale;
                if (k > 0) {
                    cout << '.' << setfill('0') << setw(k) << r % scale;
                }
                cout << "%\n";
                break;
            }
            ++k;
            scale *= 10;
        }
    }
    return 0;
}
```

### 1.6 正确性与边界

对于每个 `k`，公式恰好得到题目规定的四舍五入结果。程序从 `k=0` 开始逐个尝试，遇到第一个不是 100 的显示就退出，因此既不会使用过少的小数位，也不会多保留小数位。`x==y` 单独处理，保证真正的 100% 直接输出。

| 输入中的 x、y | 正确输出 | 检查点 |
|---|---|---|
| `1 1` | `100%` | 真实满命中 |
| `1 8` | `13%` | `12.5` 的四舍五入 |
| `199 200` | `99.5%` | 整数显示会误成 100 |
| `999 1000` | `99.9%` | 增加一位 |
| `999999 1000000` | `99.9999%` | 最大精度与中间值 |
| `1 1000000` | `0%` | 题目允许很小的非零比例显示成 0 |

时间复杂度：每组 `O(k+1)`，本题 `k≤4`，可视为 `O(1)`；额外空间 `O(1)`。

**本题值得积累的模型：输入本来是整数的比例、金额或舍入问题，先问能否用“放大后的整数＋整除”精确计算。**不是看见小数就一定要用浮点数，也不是所有小数问题都应当排斥浮点数。

## 2. 环形灯带：只枚举真正自由的选择

### 2.1 题意

`n` 盏灯围成一个环。按第 `i` 盏灯时，它自身以及左右相邻的两盏灯同时翻转。求把所有灯熄灭所需的最少操作次数；无解输出 `-1`。

`3 ≤ n ≤ 100000`，输入一个长度为 `n` 的 01 字符串，1 表示亮、0 表示灭。

如果直接搜索“下一次按哪盏灯”，既会重复，又无法承受这个规模。先改变描述方式。

### 2.2 第一步：从操作序列，转成每盏灯的操作奇偶性

两次翻转会抵消，而且这些翻转操作的先后顺序不影响最终状态。因此同一盏灯按两次等价于不按。

在最优方案中，每盏灯只需考虑按 0 次或 1 次。定义：

- `a[i]`：第 `i` 盏灯的初始状态；
- `press[i]`：是否按第 `i` 盏灯，0 为不按，1 为按一次。

`^` 表示按位异或。对 0、1 而言，它可以表示翻转：`0^1=1`，`1^1=0`。

第 `i` 盏灯的最终状态是

$$a_i\oplus press_{i-1}\oplus press_i\oplus press_{i+1}.$$

我们要求它等于 0。首尾的下标按环连接。

### 2.3 第二步：固定 press[1]、press[2]，后面就全部确定了

看第 2 盏灯：

$$a_2\oplus press_1\oplus press_2\oplus press_3=0.$$

如果 `press[1]`、`press[2]` 已知，为了让它熄灭，`press[3]` 只能取

$$press_3=a_2\oplus press_1\oplus press_2.$$

同理，对 `i=3,4,…,n`：

$$\boxed{press_i=a_{i-1}\oplus press_{i-2}\oplus press_{i-1}}.$$

这里**没有贪心选择，也没有在两个方案间取最优的 DP 转移**：每一步只有一个合法取值。

真正自由的选择只有开头两个 0/1 变量，共四组：`00、01、10、11`。分别尝试即可。

### 2.4 第三步：补上环的首尾约束

递推已经保证第 `2…n-1` 盏灯熄灭，但还没有保证第 1 盏和第 n 盏熄灭，所以必须检查：

$$a_1\oplus press_n\oplus press_1\oplus press_2=0,$$

$$a_n\oplus press_{n-1}\oplus press_n\oplus press_1=0.$$

两式都成立，这组操作才是完整方案。统计 `press` 中 1 的个数，在所有完整方案里取最小值。

这就是这里的“破环成链”：先固定处理环所需的边界变量，让中间可以线性计算，最后再验证闭合条件。**不是直接把首尾联系删掉。**

### 2.5 走一遍小例子

初始状态为 `10101`，尝试 `press[1]=0, press[2]=1`：

| 要确定的变量 | 用来熄灭哪盏灯 | 计算 | 得到 |
|---|---|---|---|
| `press[3]` | 灯 2 | `0 ^ 0 ^ 1` | 1 |
| `press[4]` | 灯 3 | `1 ^ 1 ^ 1` | 1 |
| `press[5]` | 灯 4 | `0 ^ 1 ^ 1` | 0 |

得到 `press=01110`。再检查灯 1 和灯 5，均为 0，因此这是一个按 3 次的合法方案。程序仍会检查其余三组初值，确保得到全局最少次数。

### 2.6 最终代码

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

int main() {
    int n;
    string s;
    cin >> n >> s;
    vector<int> a(n + 1), press(n + 1);
    for (int i = 1; i <= n; ++i) a[i] = s[i - 1] - '0';

    int ans = n + 1;
    for (int first = 0; first <= 1; ++first) {
        for (int second = 0; second <= 1; ++second) {
            press[1] = first;
            press[2] = second;
            int cnt = first + second;

            // 令第 i-1 盏灯熄灭，唯一确定 press[i]。
            for (int i = 3; i <= n; ++i) {
                press[i] = a[i - 1] ^ press[i - 2] ^ press[i - 1];
                cnt += press[i];
            }

            // 中间的灯已经保证熄灭，还要检查首尾两盏灯。
            if ((a[1] ^ press[n] ^ press[1] ^ press[2]) != 0) continue;
            if ((a[n] ^ press[n - 1] ^ press[n] ^ press[1]) != 0) continue;
            ans = min(ans, cnt);
        }
    }
    cout << (ans == n + 1 ? -1 : ans) << '\n';
    return 0;
}
```

### 2.7 正确性：为什么只检查四组就不会漏？

1. 任意最优操作序列都能消去成对的相同操作，得到一个每盏灯按至多一次的方案，操作次数不会增加。
2. 任意这样的合法方案，都属于四组 `press[1]、press[2]` 初值之一。
3. 固定这两个值后，合法方案必须满足递推式，因此后面的值与程序推出的值完全相同，不存在被漏掉的其他后缀。
4. 首尾检查剔除所有不能闭合的候选，剩余候选均能熄灭全部灯；取操作数最小者即得最优解。

### 2.8 实现注意点与边界

- 明确区分灯的状态 `a[i]` 与是否按灯 `press[i]`。本写法不实际修改 `a`。
- 在 1 下标数组中计算，只有读入时使用 `s[i-1]`。
- 推出 `press[i]` 时用的是 **`a[i-1]`**，因为此时要保证第 `i-1` 盏灯熄灭。
- 第 n 盏灯和第 1 盏灯都要检查，不能只检查其中一盏。
- 不能遇到第一组合法方案就返回，因为题目要最少次数。
- `n=3` 也适用，不需要另写特殊分支；此时每次按灯都会翻转全部三盏灯。
- `ans=n+1` 是“尚无合法解”的哨兵值；合法方案最多只按 n 次。

| 输入状态 | 正确答案 | 用途 |
|---|---|---|
| `n=3, 000` | 0 | 已全灭 |
| `n=3, 111` | 1 | 最小环 |
| `n=3, 100` | -1 | 无解 |
| `n=5, 10101` | 3 | 逐项推导 |
| `n=6, 111111` | 2 | 需要在合法候选中取最小值 |

时间 `O(4n)=O(n)`，额外空间 `O(n)`。

**本题的可迁移能力：当每个局部条件只涉及相邻少数变量时，先固定少量边界变量，观察后面是否会被唯一确定。**不能把“枚举前两项”机械套到所有环形题；要先写出本题的约束。

## 3. 巡检：保留贪心题解，不作为此次未完成题的诊断依据

### 3.1 题意与两个不同的量

任务 `i` 开始时至少需要 `a[i]` 电量，完成后消耗 `b[i]` 电量；每项做一次，可以调整顺序，途中不能充电。求最少初始电量。

数据范围：`1≤n≤100`，`1≤b[i]≤a[i]≤1000`。

`a[i]` 是启动门槛，`b[i]` 才是实际消耗，二者不能混为一谈。

### 3.2 固定顺序以后，答案怎样计算？

令 `used` 为前面任务已消耗的总电量，初始电量为 `E`。开始当前任务必须满足：

$$E-used\ge a_i\quad\Longleftrightarrow\quad E\ge used+a_i.$$

所以该顺序需要的最少初始电量为

$$E=\max_i(\text{任务 i 之前的消耗总和}+a_i).$$

代码中每次先更新 `ans=max(ans, used+a[i])`，再把当前消耗 `b[i]` 加入 `used`。

### 3.3 为什么按 a-b 降序？

考虑相邻的任务 A、B。先做 A 后做 B，这两项需要的最低起始电量为

$$E_{AB}=\max(a_A,\ b_A+a_B).$$

先做 B 后做 A 则为

$$E_{BA}=\max(a_B,\ b_B+a_A).$$

如果

$$a_A-b_A\ge a_B-b_B,$$

就有

$$b_A+a_B\le b_B+a_A.$$

又因为 `b_B≥0`，有 `a_A≤b_B+a_A`。于是

$$E_{AB}=\max(a_A,b_A+a_B)\le b_B+a_A\le E_{BA}.$$

因此，差值更大的任务放在前面，不会要求更高的起始电量。交换后，两项总消耗仍然是 `b_A+b_B`，不会改变后续任务得到的剩余电量。

不断消除相邻逆序，就能得到按 `a-b` 降序排列的顺序，而且答案不会变差。这才是排序贪心的依据；“看起来门槛高的先做”不足以构成证明。

### 3.4 例子

任务是 `(9,6)、(8,2)、(4,3)`，差值分别为 `3、6、1`，所以顺序为 `(8,2)、(9,6)、(4,3)`：

| 当前任务 | 开始前 used | 此任务要求的初始电量 used+a | 处理后的 ans |
|---|---|---|---|
| `(8,2)` | 0 | 8 | 8 |
| `(9,6)` | 2 | 11 | 11 |
| `(4,3)` | 8 | 12 | 12 |

答案为 12。若按 `a` 降序或按 `b` 升序，这个例子都会得到 14，说明这些直觉排序并不可靠。

### 3.5 最终代码

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

struct Job {
    int a;  // 开始时需要的最低电量
    int b;  // 完成后消耗的电量
};

int main() {
    int n;
    cin >> n;
    vector<Job> jobs(n);
    for (Job &job : jobs) cin >> job.a >> job.b;
    sort(jobs.begin(), jobs.end(), [](const Job &x, const Job &y) {
        return x.a - x.b > y.a - y.b;
    });

    int used = 0;
    int ans = 0;
    for (const Job &job : jobs) {
        ans = max(ans, used + job.a);
        used += job.b;
    }
    cout << ans << '\n';
    return 0;
}
```

### 3.6 实现注意点与复杂度

- 比较器写严格的 `>`，不能写 `>=`；差值相同的任务不需要再指定顺序。
- `used` 表示已经消耗的电量，不表示当前剩余电量。
- 单任务答案是该任务的 `a`，不是 `b`。
- 所有任务都有 `a=b` 时，答案是总消耗量。
- 本题中答案不超过 `100000`，`int` 足够；范围扩大时要重新估算。

排序 `O(n log n)`，遍历 `O(n)`；存储任务需要 `O(n)` 空间。

## 4. 三片拼板：把几何图形拆成几个简单操作

### 4.1 题意与整体分工

三块拼板分别由 `4×4` 字符图给出，`#` 是实心格，`.` 是空白。每块可以平移、旋转 90° 的整数倍，不能翻面。要求三块全部使用，恰好覆盖一个 `4×4` 棋盘，不重叠、不越界、不留空。

每块至少有一个 `#`，且块内上下左右连通。输入 12 行，每连续 4 行为一块，输出 `Yes` 或 `No`。

不应把它直接写成一个巨大的多层循环。先分成以下任务：

| 小任务 | 输入与输出/作用 |
|---|---|
| 读入形状 | 把每个 `#` 变成一个 `(r,c)` |
| 旋转 | 计算四种朝向 |
| 归一化 | 消除输入图中无意义的上侧、左侧空白 |
| 检查放置 | 判断某朝向、某平移是否越界或重叠 |
| 标记与恢复 | 放上整块，再在尝试失败后拿走整块 |
| 搜索 | 第一层放第 0 块，第二层放第 1 块，第三层放第 2 块 |

### 4.2 只存实心格，空白不属于拼板

例如形状中的实心格位于

```text
(1,2), (2,2), (2,3)
```

就用一个 `vector<Point>` 存这三个坐标。放置时只检查这三个点，不能把原 `4×4` 图里的 `.` 也当成占用。

### 4.3 旋转与归一化

0 下标 `4×4` 图中，顺时针旋转 90°：

$$\boxed{(r,c)\longrightarrow(c,3-r)}.$$

记得先保存旧行列，不能用已经更新过的 `r` 去计算新的 `c`。

旋转后，再将所有点的最小行号和最小列号分别减掉：

$$r'=r-\min r,\qquad c'=c-\min c.$$

前面的例子就归一化为

```text
(0,0), (1,0), (1,1)
```

这样每种朝向都从尽量靠左、靠上的位置开始表示，之后只需枚举非负偏移 `dr、dc`。

注意，归一化保证“至少有一个点在第 0 行，至少有一个点在第 0 列”，**不保证 `(0,0)` 本身是实心格**。不要为了让某个格子落在 `(0,0)` 而改变形状。

### 4.4 枚举放置位置

对于一种归一化朝向，枚举 `dr=0…3`、`dc=0…3`。局部点 `(r,c)` 将放到

$$\text{棋盘坐标}=(r+dr,c+dc).$$

逐个检查：

- 坐标是否落在 `0…3` 内；
- 对应棋盘格是否已经被前面的拼板占据。

**全部检查通过之后，才开始标记整块。**如果边检查边标记，一旦中途失败，还得单独恢复已经标记的半块，容易漏恢复。

为什么偏移不需要取负数？归一化后最小行、列都是 0，任何合法放置的最小棋盘行、列也必须非负，所以合法平移一定已包含在这些非负偏移中。如果不做归一化，就不能直接沿用这个枚举范围。

### 4.5 回溯状态与出口

`dfs(id)` 的含义是：

> 棋盘上已经合法放好了编号 `0…id-1` 的拼板，判断能否继续放完 `id…2`。

每层依次枚举当前拼板的 4 种朝向和 16 个平移候选：

1. 放不下，跳过。
2. 放得下，将对应格子标记为已占用。
3. 调用 `dfs(id+1)`。
4. 将刚才标记的格子全部恢复。
5. 如果下层找到解，返回 `true`。

搜索前先检查三个拼板的总实心格数是否为 16。如果不是，立即输出 `No`。如果是，那么三块都合法放下时，16 个格子互不重叠且都在棋盘内，必然恰好铺满，不需要再另查空格。

### 4.6 最终代码

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
using namespace std;

struct Point {
    int r, c;
};

vector<Point> shapes[3][4];
bool board[4][4] = {};

// 输入输出都是该拼板的实心格坐标；将最小行、列分别移到 0。
vector<Point> normalize(vector<Point> cells) {
    int minR = 4, minC = 4;
    for (Point p : cells) {
        minR = min(minR, p.r);
        minC = min(minC, p.c);
    }
    for (Point &p : cells) {
        p.r -= minR;
        p.c -= minC;
    }
    return cells;
}

// board 已放好编号 0..id-1 的拼板；尝试放好 id..2。
bool dfs(int id) {
    if (id == 3) return true;
    for (int rot = 0; rot < 4; ++rot) {
        const vector<Point> &cells = shapes[id][rot];
        for (int dr = 0; dr < 4; ++dr) {
            for (int dc = 0; dc < 4; ++dc) {
                bool ok = true;
                for (Point p : cells) {
                    int r = p.r + dr, c = p.c + dc;
                    if (r >= 4 || c >= 4 || board[r][c]) {
                        ok = false;
                        break;
                    }
                }
                if (!ok) continue;

                for (Point p : cells) board[p.r + dr][p.c + dc] = true;
                bool found = dfs(id + 1);
                for (Point p : cells) board[p.r + dr][p.c + dc] = false;
                if (found) return true;
            }
        }
    }
    return false;
}

int main() {
    int total = 0;
    for (int id = 0; id < 3; ++id) {
        vector<Point> cells;
        for (int r = 0; r < 4; ++r) {
            string row;
            cin >> row;
            for (int c = 0; c < 4; ++c) {
                if (row[c] == '#') {
                    cells.push_back({r, c});
                    ++total;
                }
            }
        }
        for (int rot = 0; rot < 4; ++rot) {
            shapes[id][rot] = normalize(cells);
            for (Point &p : cells) {
                int oldR = p.r, oldC = p.c;
                p.r = oldC;
                p.c = 3 - oldR;
            }
        }
    }
    if (total != 16) {
        cout << "No\n";
    } else {
        cout << (dfs(0) ? "Yes\n" : "No\n");
    }
    return 0;
}
```

### 4.7 正确性与实现注意点

**不漏解：**每块的四种旋转都被考虑；归一化后的每种合法平移都在枚举范围内；每个完整拼接都对应 DFS 的一条分支。因此只要有解，就会被找到。

**不误判：**每层只放不越界、不重叠的拼板；三块全部放下时总面积为 16，正好覆盖棋盘。

**回溯不串状态：**递归返回后只清除本层刚放的格子。本层放置时已确认这些格子原本为空，所以清除不会误删前面拼板的占用。

- 固定“第 0、1、2 块”的搜索顺序即可，不需要额外枚举 `3!` 种顺序。任意最终拼法都可以按这个固定顺序逐块放入。
- 对称形状可能有相同朝向，重复枚举只是多做一点工作，不影响存在性判断。当前规模不必先写去重。
- `for (Point &p : cells)` 才能实际修改坐标；去掉引用会只修改副本。
- `board[r][c]` 的访问放在越界判断之后，利用 `||` 的短路求值避免越界。
- 本写法旋转 4 次后回到原形状；不允许添加镜像变换。
- 一块能放下，不代表剩余两块也能放下，不能用“找到一个位置就固定”的贪心替代回溯。

每块最多 `Q=4×4×4=64` 个朝向与平移候选，最多 3 层，每次检查至多 16 个实心格。粗略上界为 `O(16Q³)`，这个常数规模可以直接搜索。棋盘、朝向数据与递归深度都为常数空间。

**本题对应你计划第 3 阶段的回溯，但还多了“把复杂候选生成过程拆开实现”的能力。只练选数、全排列，不能自动补齐坐标转换这一部分。**

## 5. 文本编辑器：先设计状态，再实现命令

### 5.1 先核对题目真正要求的规则

初始只有一个空行，光标在行首。光标位于字符之间。

| 命令 | 行为 | 是否形成新修改历史 |
|---|---|---|
| `INSERT s` | 在光标处插入 s，光标移到插入内容之后 | 是 |
| `LEFT / RIGHT` | 左右移动一个位置，可以跨行 | 否 |
| `UP / DOWN` | 到相邻行的当前列；行太短则停在行末 | 否 |
| `BACKSPACE` | 删除光标前的字符，光标退一位 | 实际删掉字符时才是 |
| `DELETE` | 删除光标后的字符，光标不动 | 实际删掉字符时才是 |
| `ENTER` | 光标处分行，光标到新行行首 | 是 |
| `UNDO` | 撤销最近一次未撤销的修改，恢复其刚开始前的文本和光标 | 否 |
| `REDO` | 重做最近一次撤销的修改，恢复其刚结束时的文本和光标 | 否 |

另有几条很容易漏掉的要求：

- 上下移动每次以**当前实际列号**为准，不记忆曾经更大的“目标列”。
- 删除换行符会合并两行。
- 有效的新修改清空重做历史；移动光标和无效删除不清空。
- `UNDO / REDO` 不算新修改，不清空其余待重做历史。
- 修改之间的光标移动，不改变该修改的撤销、重做恢复目标。
- 越界移动、无效删除、没有对应历史的撤销重做，都忽略。

规模：`N≤1000`，所有插入内容总长不超过 `10000`。可以保存完整状态，无需实现真实编辑器中的高效文本结构。

### 5.2 表示文本和光标：一个 string 加一个整数

用 `\n` 表示换行：

```cpp
string text = "abc\nde";
```

定义 `pos` 为**整个字符串中光标左侧的字符数，包含换行符**，因此

$$0\le pos\le text.size().$$

例如：

| 文本中的位置 | pos | 行、列 |
|---|---|---|
| 第一行 a 之前 | 0 | 第 1 行，第 0 列 |
| 第一行 c 之后、换行之前 | 3 | 第 1 行，第 3 列 |
| 换行之后、第二行 d 之前 | 4 | 第 2 行，第 0 列 |
| 第二行 e 之后 | 6 | 第 2 行，第 2 列 |

不要混淆两种“左侧字符数”：`pos` 计算全文前缀，输出的列号只计算当前行前缀。

这种表示让大部分命令变得直接：

| 操作 | 实现 |
|---|---|
| 左右移动 | `--pos` 或 `++pos`，先判边界 |
| 插入字符串 | `text.insert(pos, s)`，然后增加 pos |
| 回车 | 插入一个 `\n`，然后 `++pos` |
| 退格 | 删除下标 `pos-1`，然后 `--pos` |
| Delete | 删除下标 `pos`，pos 不变 |

删除 `\n` 就自然完成合并两行。空文本 `""` 表示一行空行；文本以 `\n` 结尾时，末尾还存在一个空行。

### 5.3 上下移动：用两个辅助函数定位行边界

`lineStart(text,pos)` 返回当前行开头在全文中的下标。向左扫描到字符串开头，或者前一个字符为 `\n` 的位置。

`lineEnd(text,pos)` 返回当前行末尾的光标位置。向右扫描到字符串结尾，或者当前字符为 `\n` 的位置。

当前列号为

```cpp
int col = pos - lineStart(text, pos);
```

设当前行起点为 `start`，终点为 `end`：

- 向上：上一行终点是 `start-1`，再找上一行起点；新位置是“上一行起点＋min(当前列号，上一行长度)”。
- 向下：下一行起点是 `end+1`，再找下一行终点；新位置是“下一行起点＋min(当前列号，下一行长度)”。

如果已经在第一行或最后一行，相应移动忽略。

例如三行长度分别为 `5、1、5`，光标在第三行第 5 列：`UP` 后到第二行第 1 列，接着 `DOWN` 到第三行**第 1 列**，不会回到第 5 列。

### 5.4 一次修改要保存“修改前”和“修改后”两个状态

```cpp
struct State {
    string text;
    int pos;
};

struct Change {
    State before, after;
};
```

这里的两份状态分别是这次修改**刚开始前、刚结束时**的状态。用两个 `vector<Change>` 当栈，栈顶在末尾：

| 情况 | 当前状态怎样改变 | 历史怎样改变 |
|---|---|---|
| 有效新修改 | 执行操作 | 将 `{before,after}` 压入 undo；清空 redo |
| `UNDO` | 恢复该修改的 before | 从 undo 弹出该修改，压入 redo |
| `REDO` | 恢复该修改的 after | 从 redo 弹出该修改，压入 undo |
| 移动或无效删除 | 按规则移动或保持原状 | 两个栈都不动 |

为什么不能简单地在撤销时把“当前状态”存进 redo？看下面的命令：

```text
INSERT abc
LEFT
UNDO
REDO
```

插入刚结束时是 `("abc",3)`，LEFT 之后变成 `("abc",2)`。UNDO 应恢复 `("",0)`，REDO 则应恢复 **`("abc",3)`**。

如果撤销时才把 `("abc",2)` 当成重做目标，文本虽然对了，光标却错了。存储修改自己的前后快照，可以直接遵守题面的恢复语义。

### 5.5 输入和输出同样属于解题的一部分

读完 `N` 后清掉这一行剩余内容，再逐条 `getline`。

`INSERT` 后只有第一个空格是命令分隔符，后面的所有字符都属于插入内容。因此：

```cpp
string s = cmd.substr(7);
```

必须保留它的前导、末尾空格。例如 `"INSERT   a "` 对应的内容为 `"  a "`。不能用 `cin >> s`、对内容使用 `getline(cin >> ws, s)`，或随意 trim。

最后输出：

1. 行数 `M`、光标行号 `R`、光标列号 `C`。行号从 1 开始，列号从 0 开始。
2. 每行加方括号，空格改成下划线。例如 `a b` 输出 `[a_b]`，空行输出 `[]`。

方括号和下划线只用于输出，不应写回编辑器内部的文本。

### 5.6 最终代码

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <limits>
using namespace std;

struct State {
    string text;
    int pos;
};

struct Change {
    State before, after;
};

int lineStart(const string &text, int pos) {
    while (pos > 0 && text[pos - 1] != '\n') --pos;
    return pos;
}

int lineEnd(const string &text, int pos) {
    while (pos < (int)text.size() && text[pos] != '\n') ++pos;
    return pos;
}

void moveUp(State &cur) {
    int start = lineStart(cur.text, cur.pos);
    if (start == 0) return;
    int col = cur.pos - start;
    int prevEnd = start - 1;
    int prevStart = lineStart(cur.text, prevEnd);
    cur.pos = prevStart + min(col, prevEnd - prevStart);
}

void moveDown(State &cur) {
    int start = lineStart(cur.text, cur.pos);
    int end = lineEnd(cur.text, cur.pos);
    if (end == (int)cur.text.size()) return;
    int col = cur.pos - start;
    int nextStart = end + 1;
    int nextEnd = lineEnd(cur.text, nextStart);
    cur.pos = nextStart + min(col, nextEnd - nextStart);
}

int main() {
    int N;
    cin >> N;
    cin.ignore(numeric_limits<streamsize>::max(), '\n');

    State cur{"", 0};
    vector<Change> undoHistory, redoHistory;

    for (int i = 0; i < N; ++i) {
        string cmd;
        getline(cin, cmd);

        if (cmd == "LEFT") {
            if (cur.pos > 0) --cur.pos;
            continue;
        }
        if (cmd == "RIGHT") {
            if (cur.pos < (int)cur.text.size()) ++cur.pos;
            continue;
        }
        if (cmd == "UP") {
            moveUp(cur);
            continue;
        }
        if (cmd == "DOWN") {
            moveDown(cur);
            continue;
        }
        if (cmd == "UNDO") {
            if (!undoHistory.empty()) {
                Change change = undoHistory.back();
                undoHistory.pop_back();
                cur = change.before;
                redoHistory.push_back(change);
            }
            continue;
        }
        if (cmd == "REDO") {
            if (!redoHistory.empty()) {
                Change change = redoHistory.back();
                redoHistory.pop_back();
                cur = change.after;
                undoHistory.push_back(change);
            }
            continue;
        }

        State before = cur;
        bool changed = false;
        if (cmd.substr(0, 7) == "INSERT ") {
            string s = cmd.substr(7);  // 只去掉指令及一个分隔空格
            cur.text.insert(cur.pos, s);
            cur.pos += (int)s.size();
            changed = true;  // 题目保证 s 非空
        } else if (cmd == "ENTER") {
            cur.text.insert(cur.pos, 1, '\n');
            ++cur.pos;
            changed = true;
        } else if (cmd == "BACKSPACE") {
            if (cur.pos > 0) {
                cur.text.erase(cur.pos - 1, 1);
                --cur.pos;
                changed = true;
            }
        } else if (cmd == "DELETE") {
            if (cur.pos < (int)cur.text.size()) {
                cur.text.erase(cur.pos, 1);
                changed = true;
            }
        }

        if (changed) {
            undoHistory.push_back({before, cur});
            redoHistory.clear();
        }
    }

    int M = 1 + (int)count(cur.text.begin(), cur.text.end(), '\n');
    int R = 1 + (int)count(cur.text.begin(), cur.text.begin() + cur.pos, '\n');
    int C = cur.pos - lineStart(cur.text, cur.pos);
    cout << M << ' ' << R << ' ' << C << '\n';

    string row;
    for (char ch : cur.text) {
        if (ch == '\n') {
            cout << '[' << row << "]\n";
            row.clear();
        } else {
            row.push_back(ch == ' ' ? '_' : ch);
        }
    }
    cout << '[' << row << "]\n";  // 包括末尾空行
    return 0;
}
```

### 5.7 为什么这个实现正确？

维护以下不变式：

- `text` 准确记录所有行及其换行分隔，`pos` 准确记录当前光标位置；
- undo 栈顶是最近一次尚未撤销的修改；redo 栈顶是下一次应重做的修改；
- 每个修改对象的前后状态在建立后保持不变。

普通编辑命令按字符串下标实现题目操作；上下移动通过行边界得到准确的行长和当前列号。有效修改保存前后状态并清空 redo；UNDO、REDO 只在两个栈之间移动同一个修改对象，并恢复其固定目标。因而每执行一条命令，上述不变式仍成立。由初始空文本、零光标出发，所有命令处理后即得到正确结果。

设 `L` 为过程中最大文本长度，包含换行符，`L≤10000+N`。字符串插删、行定位和快照复制最多 `O(L)`，总时间为 `O(NL)`，保存历史的空间为 `O(NL)`。按本题规模和讲评的保存完整状态思路即可；无需为了追求单条命令 `O(1)` 引入复杂结构。

### 5.8 建议手测的命令组合

下面每个测试独立从空编辑器开始；输入时在第一行补上命令条数。

| 命令顺序 | 应关注的结果 |
|---|---|
| `BACKSPACE → DELETE → LEFT → UP → UNDO → REDO` | 始终一行空行，行 1 列 0 |
| `ENTER → ENTER` | 三行空行，行 3 列 0；最后一行不能丢 |
| `INSERT abc → LEFT → UNDO → REDO` | 恢复 abc，光标列 3 |
| `INSERT a → UNDO → BACKSPACE → LEFT → REDO` | 无效删除、移动不破坏重做，最后是 a，列 1 |
| `INSERT a → UNDO → INSERT b → REDO` | 新修改清空重做，最后仍是 b |
| `INSERT ab → ENTER → INSERT cd → LEFT → LEFT → LEFT → DELETE` | 删除换行，得到 abcd，列 2 |
| 长行末尾 → UP 到短行 → DOWN 回长行 | 使用短行上的实际列号 |
| 插入包含前导和末尾空格的内容 | 空格保留，输出时转为下划线 |

**本题的大模拟能力，主要不是能否记住很多分支，而是能否用一个统一的状态表示，让多条规则共享同一套含义。**

## 6. 从四道未完成题提炼你的训练重点

### 6.1 能确定什么，怎样进一步定位？

从题目本身可以确定：四题的要求不同，单靠多学几个算法名称不足以全部覆盖。仅凭“没做出”，还不能判断你当时究竟卡在思路、实现还是时间；应当通过分层重做定位。

| 重做时的表现 | 更可能需要补的环节 | 下一步训练 |
|---|---|---|
| 无法说出保存什么、枚举什么 | 问题表示与建模 | 暂不写代码，画状态表、写局部约束 |
| 能说出模型，但不会把步骤分成函数 | 实现分解 | 只实现并验证一个小模块，再组合 |
| 能写出主体，但首尾、空状态反复错 | 不变式与边界设计 | 明确变量合法范围，按边界分类造测试 |
| 看题解能懂，隔天独立写不出来 | 提取与重建能力不足 | 关掉题解重写，并做改变条件的变式 |
| 单题能做，整卷来不及 | 熟练度和考场调度 | 混合题限时，记录起步、编码、调试用时 |

一次有用的自测：先不给自己看代码，用一张纸分别写出四题的状态、核心公式/约束、枚举范围、终止条件。再开始编码。这样能把“不会想”和“不会写”区分开。

### 6.2 第一类：精确计算能力——对应缓存命中率

**要练的是：把自然语言规则翻译成可计算的等式，并估算中间值。**

建议按三步练，每步只做一个小任务：

1. 给定正整数 `a,b`，输出 `a/b` 四舍五入后的整数。先手算 `1/2、3/2、4/3`，推导公式，不调用 `round`。
2. 给定正整数 `a,b` 和 `k≤4`，精确输出保留 k 位小数的非负比例；专门测半值、进位、小数部分需要补零的情况。
3. 回到缓存题，加入“只有误成 100 才增加精度”的规则。改变 x、y 的范围，重新判断是否可能溢出、循环最多多少次。

**验收：**不看答案推导舍入公式，解释为什么不会整数除法过早截断，写出最大中间值。只记住 `(200*x*scale+y)/(2*y)` 还不算会迁移。

### 6.3 第二类：从局部约束推出全局——对应环形灯带

这类题最需要补的是**观察哪些选择真正自由、哪些选择已经被前面的条件强制确定**。它有算法思维，但不要求先学高级算法。

按下面的阶梯做，比反复背环形灯带的四情况模板更有效：

1. **链形、翻转自己和右邻灯：**最后一盏只翻转自己。从左往右看，为了熄灭最左边还未确定的灯，当前操作是否还有选择？
2. **链形、翻转自己和左右邻灯：**边界只翻转实际存在的灯。尝试先固定第一盏是否按，推导后面，最后检查尾灯。为什么只需要两组初值？
3. **环形、翻转自己和左右邻灯：**回到本题，解释为什么改为枚举两个初值，为什么多了两个闭合检查。

前两个任务也要求最少操作数或输出无解，但先只在小规模上手算，再编码。对 `n≤10`，另外写一个枚举所有按法的慢程序，与快速程序逐组对照。这个慢程序是调试工具，不是最终复杂度。

**验收：**看到一个新局部规则，能先写出“某盏灯最终为 0”的等式，再判断需要固定多少初值；不会因为题目出现“最少”就立即套 BFS、DP 或贪心。

### 6.4 第三类：候选生成＋回溯实现——对应三片拼板

按现有八阶段计划，回溯属于第 3 阶段，但这题还需要额外练坐标和模块组合。

建议分四次完成，不要第一轮就限时写完整题：

1. **只练变换：**读一块形状，输出四次旋转后的坐标；验证旋转四次回到原形状，点数与相对形状保持不变。
2. **只练放置：**给定一块形状和一个已有占用的棋盘，枚举所有合法放置，暂不递归。
3. **只练恢复：**放一块、再拿走，比较棋盘是否逐格回到原状；再做两块能否无重叠放入的判断。
4. **完整组合：**加入第三块和面积 16 的前置判断，写成完整 DFS。

每一步都先明确函数契约，例如：`dfs(id)` 进入时前 id 块已放好，返回时棋盘恢复成进入时的样子。这样不用在每次递归时重新猜哪些数据应该保留。

**验收：**能独立解释搜索树每层的含义、候选是否枚举完整、为什么清除本层格子不影响前面拼板。换成 `5×5` 棋盘或不同块数时，知道哪些部分只需改常量，哪些部分的复杂度会明显增长。

### 6.5 第四类：状态设计＋规则组合——对应文本编辑器

不要以“我再做五道大模拟”作为唯一训练计划。先把一题拆成可独立验收的几个版本：

| 版本 | 功能范围 | 必测情况 |
|---|---|---|
| A：单行编辑器 | 插入、左右移动、退格、Delete | 空文本、首尾、插入空格 |
| B：多行编辑器 | 增加 Enter 和跨行左右移动 | 连续空行、行首退格、行末 Delete |
| C：二维移动 | 增加 Up、Down | 长短行切换、首尾行、实际列号 |
| D：修改历史 | 增加 Undo、Redo | 修改与移动交错、无效删除、新修改清空 redo |

每次加功能，只先测试新规则和它与旧规则的交叉。特别是版本 D，不能只测试连续的 `INSERT → UNDO → REDO`，还要插入光标移动和无效命令。

**验收：**不看完整代码也能写出状态结构、命令分类表、历史栈转移表；能解释为什么一个新变量必要，或者为什么一个分支可以由统一表示自然处理。

这部分可以在第 7 阶段系统练，但基础模块现在就能穿插做，不必等学完 DP 才开始。

### 6.6 贯穿四题：怎样练独立调试？

不要从“最后输出不对”直接跳到随意改循环边界。按下面顺序做：

1. **先写手算的预期状态。**例如灯带的 press 数组、巡检的 used/ans 表、编辑器每条指令后的 text/pos。
2. **定位第一处偏离。**按循环或命令逐步检查，找到最早出现错误的中间状态，而不是只盯着最终答案。
3. **区分错误层次。**是模型不对、公式不对、候选漏了、状态没恢复，还是仅仅输出格式错了？
4. **保留最小失败用例。**删去无关命令、缩小棋盘形状或输入规模，让它只展示一个错误。
5. **修正后重跑相关边界。**例如修复行首退格后，同时检查行末 Delete 与末尾空行，防止改动破坏相邻规则。

| 题目 | 最值得观察的变量/状态 | 可以直接检查的不变式 |
|---|---|---|
| 缓存 | k、scale、r | `scale=10^k`；每次从原始 x/y 重算 |
| 灯带 | 固定初值、press 数组 | 计算到 press[i] 后，第 2…i-1 盏灯的方程成立 |
| 拼板 | id、朝向、偏移、board | 递归返回后 board 与调用前一致 |
| 编辑器 | 当前指令、text、pos、两栈大小 | `0≤pos≤text.size()`；历史对象的恢复目标不随光标移动改变 |

在 VSCode 中，断点应设在“状态刚发生变化”的位置：更新 press 之后、放置/恢复棋盘之后、执行命令之后。能够指出该处变量应该是多少，断点才有用。

### 6.7 训练安排与考场迁移

一轮训练采用“**理解母题 → 关答案实现 → 改一个关键条件 → 混合题识别 → 隔天重写**”。母题提供可迁移的结构，变式检验你是否真正理解了结构成立的条件。

优先级建议：

1. 先补缓存题和灯带题的建模过程。两题代码量小，便于把“是否想明白”与“是否能写出来”分开。
2. 在第 3 阶段用拼板补上坐标变换、合法性判断和回溯组合。
3. 用分版本的文本编辑器集中练实现能力，不要求第一次就一次写完全部规则。
4. 再把这些题与其他类型混在一起限时，训练没有题型提示时的识别和取舍。

第一次复盘不必限时，先形成可靠模型；之后分别记录“得到完整思路、写完代码、修到正确”三个时间点。**正确性还未稳定时，压缩打字时间通常不是最优先的补救。**

在 180 分钟、9 题的考试中，平均每题 20 分钟只是总时间除法，不能据此要求每题等长。读完题先判断自己能否说出完整状态和处理流程：

- 有完整方案的题先兑现，给实现量较大的题保留专门时间。
- 思路尚未建立时，先写关键约束或小例子；若仍没有推进，标记后切换，稍后回看。
- 大模拟动手前，先用几分钟列出状态和命令分类，避免写到一半才发现历史语义或输入格式理解错了。
- 每题至少准备一个正常样例和一个最小/边界样例再提交。

**针对你这次的四题，最值得补强的主线是：精确表示问题、从约束推出可执行步骤、把步骤拆成可验证模块，以及用中间状态调试。**算法模型和大模拟都是这条主线的不同部分，不能只补其中一个。
