**1．下标和区间：需要根据“访问了什么”推导循环范围**

证据一：[homework/2-1-4.cpp：9行](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/homework/2-1-4.cpp#L9)。

循环条件是 `i < v.size()`，但循环体访问 `v[i+1]`。最后一轮必然读取 `v[v.size()]`。这不是只在特殊数据上答案偏一点，而是访问范围已经不成立。本轮用边界检查编译后，输入单个元素即可中止程序。

更深一层的问题是：最长连续段只在“下一项不同”时结算。修复越界时，还必须重新检查末尾那段何时计入答案。不能只把条件中的一个数字改掉，就认为整个功能已修好。

证据二：[homework/2-2-5.cpp：75行](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/homework/2-2-5.cpp#L75)。

回形遍历检查横向边界时使用 `arr[1].size()`。它隐含“至少两行”的假设；1×3 输入会在访问第二行时失败。行数、列数应来自输入或明确的维度变量，不应依赖某一行碰巧存在。

证据三：[mock exam/2024-3.cpp：16行](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/mock%20exam/2024-3.cpp#L16)。

应固定的动作：

- 写循环前先问：本轮是否访问 `i-1`、`i+1`，或另一个容器的同一下标？

**2．坐标与变量含义：数学表达式需要落实为离散下标**

证据：[homework/2-5-8.cpp：26行](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/homework/2-5-8.cpp#L26)。

你用 `r0=(n-1)/2` 表示中心，再用 `2*r0-i` 表示镜像位置。对奇数 n 有 `2*r0=n-1`，对偶数 n 却有 `2*r0=n-2`。整数除法丢掉了半格。

因此你写出的数学推导有直观意义，但代码表示改变了推导的前提。顺时针旋转的下标应直接从原矩阵推到目标矩阵：

`(row,col) -> (col,n-1-row)`

还应注意 `clock` 上方写着“判断逆时针”，`counter` 上方写着“判断顺时针”。注释与函数名相反，会在调试时让你额外确认方向。

这里的训练重点是：先确定“源格子搬到目标哪里”，再写比较。用四角互不相同的 2×2 矩阵手算，比用全相同矩阵更有区分力。

矩阵文件未保存完整题干。本轮以允许偶数阶检验；若原题额外限定奇数阶，应把偶数阶问题归为推广写法的漏洞，而非该题已确认的 WA。

**3．循环状态：索引和计数需要始终对应题意中的对象**

证据：[homework/2-6-7.cpp：20行](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/homework/2-6-7.cpp#L20)，题目是习题课的“魔王军队”。

代码先让 `cur` 离开“距 left 不超过 R”的区间，注释却把它同时称为“下一个 left”，并说石头放在 `cur-1`。这两个位置并不相同：

1. 从最左未覆盖士兵出发，找到 R 内最右侧的士兵，把石头放在那里。
2. 再以石头为中心向右走 R，跳过全部已覆盖士兵。

你的实现没有完整表达第二步；末尾又用 `result--` 修补计数。因此单个士兵输出 0，4 个士兵位于 0、10、20、30 且 R=10 时输出 1，实际需要 2。

应固定的动作：

- 在循环开始规定：`next` 指向第一个未覆盖士兵。
- 临时变量 `stone` 只表示石头所在位置。
- 一次完成放石头及跳过覆盖区后，计数加一。
- 循环结束时，`next` 恰好指向下一个未覆盖士兵或末尾后一位。

这叫循环不变量，含义很简单：每一轮都维持同一句状态说明。你现在需要的是在熟悉题意后练习这种表达，不必为此另学一套贪心算法。

**7．代码习惯：哪些要马上改，哪些优先级较低**

马上改的习惯：

1. **命名携带含义。** 常用 count、index、Pair 本身没有错，但长函数中多个“某个计数／某个下标”容易混淆。优先使用 currentRun、bestRun、firstUncovered、stoneIndex、integerPart、fractionPart。
2. **注释说明约定。** “sort”“处理输入”作用有限；“已覆盖范围为 [0,next)”“借位为 0 或 -1”“cut 是前缀长度”才能帮助排查。
3. **每完成一层就验收。** 本轮最典型的缺口是补齐后不检查长度、运算后不检查原始结果。
4. **检查循环最后一轮和最后一段。** 不靠访问下一项来碰巧触发结算。
5. **输出也要有固定模板。** 每组结尾换行，分隔符在第二项及之后输出；复杂结果由 format 函数统一生成。
6. **笔记按可执行规则更新。** 旧笔记和新笔记应合并，避免再次记忆错误版本。

笔记中的具体问题：

- [notes/L8.md](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/notes/L8.md) 写“string 是 length()，不是 size()”，实际二者都可用。

较低优先级：只读参数统一为 const 引用、删除不用的头文件、清理旧代码和过多空行、自定义比较器采用 const 参数。它们有助于阅读和性能，但在本次备考中应排在越界、状态错误和输出错误之后。

- 补充数据：交换两串；1+1；111+1；位数接近上限的全 1 数相加。
- 调试时停在补齐之后：两串长度是否相同？停在每轮之后：是否恰好产生一位结果？
- 验收：操作数交换不改变和；最终进位被保留；不转换为内置整数。

**④ 罗马数字与整数转换：[mock exam/2024-8.cpp](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/mock%20exam/2024-8.cpp)**

主要训练：共享重复规则、减少独立分支。

- 复现输入：658。预期 DCLVIII，当前 DLVIII。
- 另一输入：600。预期 DC，当前运行抛出字符串长度异常。
- 补充数据：4、9、40、90、400、900、3999；以及对应的罗马数字反向转换。
- 调试时查看百位分支读取了哪个位变量。
- 验收：同一条规则只定义一次；对所有 1—3999 的整数检查“转罗马再转整数仍等于原数”。这只是 3999 个测试，很适合本题。

**⑤ 魔王军队：[homework/2-6-7.cpp](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/homework/2-6-7.cpp)**

主要训练：两阶段扫描和循环不变量。题意见 how_to_code_better 中第二份习题课 PDF 第 2—3 页。

- 复现输入：`10 1\n100\n-1 -1\n`。预期 1，当前 0。
- 第二输入：`10 4\n0 10 20 30\n-1 -1\n`。预期 2，当前 1。
- 第三输入：R=10，9 个士兵位于 0、10、…、80。预期 3，当前 4。说明不能只删去 result-- 就宣布修复。
- 补充数据：R=0 且位置重复；距离恰好等于 R；最后一个士兵刚好被覆盖。
- 验收：每轮都分别完成“选石头”和“跳过覆盖区”；计数只在实际放置石头时增加；无需事后减一补救。

**⑥ 两个长的 k 进制数相减：[mock exam/2025-9-new.cpp](https://github.com/Tranquil-ink/fcpp-learning/blob/4169c6a27b71c0c6d1db3a8e20d5dc4d28d77e7a/mock%20exam/2025-9-new.cpp)**

主要训练：分模块调试，独立格式化。

- 复现输入：`1\n10 .2 .1\n`。预期 .1，当前 0。
- 另一输入：`1\n10 2 1\n`。预期 1，当前在 1 后输出小数点和大量零。
- 多组输入：`2\n10 .2 .1\n10 .4 .1\n`。预期两行 .1、.3，当前连续输出 00。
- 补充数据：10 1 1；10 -2 -1；10 1 -2；10 1 .9；16 A 1。
- 调试顺序：parse → 原始运算结果 → format。先定位第一个不符合预期的层。
- 验收：每层均可独立检查；整数、小数、零、负数格式正确；组间换行。

**如何把复盘变成调试训练**

对每题只留下四项记录：

1. 最小失败输入，以及手算结果。
2. 程序首次偏离预期的位置和变量。
3. 错误类别，如访问范围、表示不统一、字段复制错误、状态含义改变。
4. 修复后必须继续通过的几个测试。

“注意边界”“下次细心”太宽泛。更有用的记录是：“循环访问 i+1，因此最大 i 为 n-2；连续段在循环末尾也要结算”。

断点只设在需要检验猜测的位置。例如怀疑末轮越界，就在比较语句处检查 i 和 n；怀疑补零错误，就在补零后查看两串；怀疑运算结果错，就先看格式化之前的结构体。程序输出 0 时，不要立即改借位公式。

本地练习可以开启常用警告及边界检查。例如 GCC 环境的 `-Wall -Wextra -g -D_GLIBCXX_ASSERTIONS`。考试环境未必提供同样选项，边界检查不能替代你自己的范围推导。警告也需逐条理解：日期计算故意让 switch 贯穿 case 就不应机械地补上 break。
