题目
第 1 题 求亲和数

题目描述　遥远的古代，人们发现某些自然数之间有特殊的关系：设有两个数a和b，若a的所有除本身以外的因数之和等于b，b的所有除本身以外的因数之和等于a，则称a、b是一对亲和数。

例如220和284：220的真因数包括：1,2,4,5,10,11,20,22,44,55,110. 1 + 2 + 4 + 5 + 10 + 11 + 20 + 22 + 44 + 55 + 110 = 284；284的真因数包括：1,2,4,71,142. 1 + 2 + 4 + 71 + 142 = 220。所以220和284是一对亲和数。

关于输入　一个正整数n，1<=n<=100000。

关于输出　所有亲和数对"a b"，满足a和b均小于等于n。每个亲和数对占一行，两个数之间用一个空格隔开，较小数在前，较大数在后。对于多个亲和数对，以较小数递增的顺序输出它们。

例子输入
1500
例子输出
220 284
1184 1210
计算概论A · 习题课
解法一 · 质因数分解

思路先分解，再用公式求因数和

部分同学的做法：把 \(a\) 分解为 \(a=p_1^{k_1}\cdot p_2^{k_2}\cdots\)，全部因数之和 \(\sigma(a)=\prod_j\left(1+p_j+\cdots+p_j^{k_j}\right)\)，真因数和就是 \(\sigma(a)-a\)；算出 \(b\) 后，再分解 \(b\) 验证 \(\sigma(b)-b\) 是否等于 \(a\)。

例子：\(a=12\) 的因数和
分解质因数：\(12 = 2^2 \cdot 3^1\)，套用公式 \[\sigma(12) = (1+2+2^2)\times(1+3^1) = (1+2+4)\times(1+3) = 7\times 4 = 28.\] 为什么成立：乘积展开时每个括号各选一项，恰好枚举出全部因数（如 \(2^0\cdot3^0=1\)、\(2^2\cdot3^1=12\)）。 验证：12 的因数有 \(1, 2, 3, 4, 6, 12\)，加起来正好是 28。
实际作业中
用这套思路的同学往往还先写一个质数筛（埃氏筛）：筛出 \(10^5\) 以内的素数，分解时只拿素数试除、跳过合数。思路没错，但代码又多了一层——下一页是包含筛法的完整程序。
小贴士 · 数组：储存一系列数在某一维度上的性质 / 状态（是否是质数？是否被传染）——如下一页的 composite[] 就是「是否合数」。

amicable1.cpp 
#include <iostream>
using namespace std;

const int N = 100000;
bool composite[N + 1];          // 合数标记：composite[i] 为 true 表示 i 是合数
int primes[N], primeCount;      // primes[] 存放筛出的素数，primeCount 记录个数

// 埃氏筛：收集 n 以内的所有素数
// 核心思想：未被标记为合数的数就是素数；每找到一个素数 i，就把它的所有倍数标记为合数
void sieve(int n) {
    for (int i = 2; i <= n; i++) {          // 从 2 开始逐个检查
        if (composite[i]) continue;         // i 已被更小的素数标记过：是合数，跳过
        primes[primeCount++] = i;           // 未被标记：i 是素数，存入 primes[]
        for (int j = i + i; j <= n; j += i)  // 从 2i 开始、步长为 i，枚举 i 的所有倍数
            composite[j] = true;            // 把这些倍数全部标记为合数
    }
}

// x 的全部因数之和（含 1 和 x 本身）
int sigma(int x) {
    int sum = 1;
    for (int j = 0; primes[j] * primes[j] <= x; j++) {
        int p = primes[j];
        if (x % p) continue;
        int term = 1, pk = 1;          // 累加 1 + p + ... + p^k
        while (x % p == 0) {
            x /= p;
            pk *= p;
            term += pk;
        }
        sum *= term;
    }
    if (x > 1) sum *= 1 + x;           // 还剩下一个大于 sqrt(x) 的素因子
    return sum;
}

int main() {
    sieve(N);
    int n;
    cin >> n;
    for (int a = 2; a <= n; a++) {
        int b = sigma(a) - a;          // a 的真因数之和
        if (b > n || b <= a) continue;
        if (sigma(b) - b == a)
            cout << a << " " << b << "\n";
    }
    return 0;
}
结论
思路正确，提交后可以通过本题。
代价
  • 筛法、分解、公式求和、二次验证，每个环节都可能写错
  • 只用素数试除，一次分解要试除 \(\pi(\sqrt{x})\approx\dfrac{\sqrt{x}}{\ln\sqrt{x}}\) 个素数——比逐个枚举 \(d\) 少一个对数因子，但总量仍是 \(n^{3/2}\) 级别，没有质变
  • 本题 \(n\le 10^5\)，这套方法用不上

解法二 · 直接枚举

思路枚举因数到 \(\sqrt{x}\) 即可

因数成对出现：\(d\) 是 \(x\) 的因数，\(x/d\) 也是。只需枚举 \(d\le\sqrt{x}\)，一次得到两个因数。
写函数 sumDiv(x)，返回 x 的真因数之和。
对每个 \(a\in[2,n]\)，令 b = sumDiv(a)；若 \(b\le n\) 且 sumDiv(b) == a，则 \((a,b)\) 是一对。
只输出 \(a<b\) 的对，顺序和不重复都能保证。
复杂度
单个 sumDiv 是 \(O(\sqrt{a})\)，总计 \(\sum_{a=2}^{n}\sqrt{a}\approx\frac{2}{3}n^{3/2}\)。\(n=10^5\) 时约 \(2\times10^7\) 次运算，可以通过。

解法二 · 直接枚举

注意容易出错的两处

完全平方数
\(x\) 是完全平方数时（如 \(36=6\times6\)），枚举到 \(d=6\) 时 \(d\) 与 \(x/d\) 是同一个数，不判断会重复累加，结果偏大。应写 if (d * d != x) sum += x / d;。
另一个数可能超过 n
\(b = \mathrm{sumDiv}(a)\) 可能大于 \(n\)，例如 \(n=250\) 时 \(a=220\) 的伙伴是 284。必须先判断 \(b\le n\) 再验证和输出，否则多出不合法的数对。
补充
  • 用 b <= a 跳过，可以同时解决「每对只输出一次」和「完全数（b = a）不算亲和数」两个问题。
  • 枚举边界写成 d * d <= x：不用除法，也不用浮点 sqrt，整数判断没有精度问题。
小贴士：利用报错 / 自己设计一些数据，看是不是有些边界条件没考虑到。

amicable2.cpp 
#include <iostream>
using namespace std;

// x 的真因数之和（不含 x 本身）
int sumDiv(int x) {
    int sum = 1;                       // 每个 x > 1 都有因数 1
    for (int d = 2; d * d <= x; d++) { // 枚举到 sqrt(x) 为止
        if (x % d == 0) {
            sum += d;
            if (d * d != x)            // 平方根只计一次
                sum += x / d;
        }
    }
    return sum;
}

int main() {
    int n;
    cin >> n;
    for (int a = 2; a <= n; a++) {
        int b = sumDiv(a);
        if (b > n)  continue;          // 伙伴不能超过 n
        if (b <= a) continue;          // 每对只输出一次，保持 a < b
        if (sumDiv(b) == a)
            cout << a << " " << b << "\n";
    }
    return 0;
}
要点
  • 循环条件写 d * d <= x：整数乘法判断，没有浮点 sqrt 的精度问题；本题 \(d^2\le x\le 10^5\)，不会溢出
  • \(b>n\) 与 \(b\le a\) 两个判断都要有；验证是双向的
  • 对比上一解法：没有筛法、没有公式，一个函数讲清一件事

第 2 题 除法计算

题目描述　小P正在计算一个正整数除法a/b，但是他并不想知道结果具体是多少，他只想知道将结果化为小数之后，形成的循环节长度是多少。例如:1 / 90的结果为0.011111...，循环节长度为1。如果结果不为循环小数，则认为循环节长度是0。

关于输入　两个正整数a,b,满足1≤a,b≤1000。

关于输出　输出a/b循环节长度。

例子输入
2 7
例子输出
6
验证
\(2/7 = 0.\overline{285714}\)，循环节 285714 长 6；\(1/90 = 0.0\overline{1}\)，循环节长 1。
计算概论A · 习题课
解法一 · 模拟

思路余数决定一切

长除法每一步只依赖当前余数 \(r\)：下一位数字是 \(\left\lfloor\frac{10r}{b}\right\rfloor\)，新余数是 \(10r \bmod b\)。
余数一旦相同，后面的数字完全重复。余数只有 \(b\) 种取值（\(0\) 到 \(b-1\)），所以至多 \(b+1\) 步必出现重复——循环节一定存在。
若某一步余数变成 \(0\)，小数到此结束，是有限小数，答案为 \(0\)。
算法：开数组 pos，pos[r] 记录余数 \(r\) 第一次出现的位置。从 \(r = a \bmod b\) 出发，每步先记录当前余数的位置，再令 \(r \leftarrow 10r \bmod b\)，直到余数变成 \(0\)（输出 \(0\)）或撞上已记录过的余数（输出两次位置之差）。
样例验证（2/7）
余数依次为 \(2,6,4,5,1,3,2\)：第 7 个余数重复，首次出现位置从 \(0\) 计起，间隔 \(6-0=6\)，正是循环节 \(285714\) 的长度。
呼应第 3 页：余数只有 \(b\) 种可能 → 重复即循环 → 用数组记状态——pos[r] 存的正是「余数 \(r\) 的状态」。

解法一 · 模拟

代码记余数，第一次重复即循环节

cycle.cpp 
#include <iostream>
#include <cstring>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;
    int pos[1005];                  // pos[r]：余数 r 第一次出现的位置
    memset(pos, -1, sizeof(pos));
    int r = a % b;                  // 跳过整数部分
    int cur = 0;                    // 目前已产生的小数位数
    while (r != 0 && pos[r] == -1) {
        pos[r] = cur;
        r = r * 10 % b;
        cur++;
    }
    if (r == 0) cout << 0 << endl;  // 有限小数
    else cout << cur - pos[r] << endl;
    return 0;
}
要点
  • pos[r] 记录余数第一次出现的位置，−1 表示没出现过
  • 余数变 0：有限小数，输出 0；余数重复：间隔 cur - pos[r] 就是循环节长度
  • \(O(b)\) 时间 \(O(b)\) 空间，不需要任何数论知识
运行结果
输入  2 7
输出  6

解法二 · 数论

思路循环节长度是 \(10\) 的阶

先约分（分子分母同除以 \(\gcd(a,b)\)），答案只与约分后的分母 \(b'\) 有关：分子不改变小数部分的循环结构。
有限小数，当且仅当 \(b'\) 的素因子只有 \(2\) 和 \(5\)（把 \(2\)、\(5\) 除光后剩下 \(1\)），此时答案为 \(0\)。
例如 \(\frac18=0.125\)（分母 \(8=2^3\)）、\(\frac1{20}=0.05\)（分母 \(20=2^2\cdot5\)）。
否则，循环节长度等于最小的正整数 \(t\)，使 \(10^{t}\equiv 1\pmod{b'}\)。
理由：小数部分以 \(t\) 为周期，当且仅当 \(\frac{a}{b'}\) 与 \(\frac{10^{t}a}{b'}\) 的小数部分相同，当且仅当 \(b'\mid a(10^{t}-1)\)。
又 \(\gcd(a,b')=1\)，故当且仅当 \(b'\mid(10^{t}-1)\)。
这样的 \(t\) 必然存在：去掉因子 \(2\)、\(5\) 后 \(\gcd(10,b')=1\)，欧拉定理给出 \(10^{\varphi(b')}\equiv 1\pmod{b'}\)，且 \(\varphi(b')\le b'-1\le 999\)，从小到大枚举 \(t\) 必能命中。
验证
\(1/90\)：约分后 \(b'=9\)，\(10^{1}\equiv 1\pmod 9\)，长度 \(1\)。\(2/7\)：\(b'=7\)，\(10^{6}\equiv 1\pmod 7\) 且更小的 \(t\) 都不行，长度 \(6\)。

解法二 · 数论

代码约分、去 2/5、找阶

cycle2.cpp 
#include <iostream>
using namespace std;

int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }

int main() {
    int a, b;
    cin >> a >> b;
    b /= gcd(a, b);              // 约分：分子分母同除以 gcd
    while (b % 2 == 0) b /= 2;   // 去掉因子 2
    while (b % 5 == 0) b /= 5;   // 去掉因子 5
    if (b == 1) {                // 只剩因子 2、5：有限小数
        cout << 0 << endl;
        return 0;
    }
    int p = 10 % b;
    for (int t = 1; ; t++) {     // 最小的 t 使 10^t ≡ 1 (mod b)
        if (p == 1) { cout << t << endl; break; }
        p = p * 10 % b;
    }
    return 0;
}
要点
  • \(p\) 始终等于 \(10^{t}\bmod b\)：初始 \(p = 10\bmod b\)，每步 \(p\leftarrow 10p\bmod b\)，与 \(t\) 同步递增
  • 第一次出现 \(p=1\) 时的 \(t\) 就是阶，即循环节长度
  • 与 \(999\ldots9\) 取模判法等价：\(b\mid\underbrace{99\cdots9}_{t}\iff 10^{t}\equiv 1\pmod b\)；全程 \(O(b)\)

第 3 题 计算两个日期之间的天数

题目描述　给定两个年月日，计算之间的天数。例如 2010-1-1 和 2010-1-3 之间差2天。

关于输入　第一行 startYear startMonth startDay；第二行 endYear endMonth endDay。

关于输出　输出只有一行是两个日期之间的天数。

例子输入
2008 1 1
2009 1 1
例子输出

计算概论A · 习题课
闰年

规则闰年怎么判断

题干已经给出规则：(year % 4 == 0 && year % 100 != 0) || (year % 400 == 0)

年份能否被 4 整除是否闰年
2008能，且不是整百年是
1900能，但是整百年，不能被 400 整除否
2000能，是整百年，且能被 400 整除是
含义
闰年 366 天，平年 365 天，差别只在二月（29 天或 28 天）。规则分两层：先要求能被 4 整除；整百年（如 1900、2100）例外，必须能被 400 整除才算。
常见错误
只写 year % 4 == 0，会把 1900、2100 误判为闰年，二月按 29 天算，结果出错。这道题的数据范围到公元 3000 年，2100、2200 这类年份一定会被测试到。

另解 · 逐年逐月累加

做法不换算，按整年整月累加

先归一化：若 start 晚于 end，交换两者，最后取非负差即可。
补足年份：当 \(y_1<y_2\) 时，累加「从当前日期到当年 12 月 31 日」的天数，再把日期推进到下一年的 1 月 1 日。
补足月份与天数：同一年内按整月累加（2 月看 isLeap 给 28/29），最后加 \(d_2-d_1\)。
yearmonth.cpp 
// 若 start > end，交换两者
while (y1 < y2) {              // 补足年份
    days += daysToYearEnd(y1, m1, d1);
    y1++; m1 = 1; d1 = 1;
}
while (m1 < m2) {              // 补足月份
    days += daysInMonth(y1, m1);   // 2 月按 isLeap 给 28/29
    m1++;
}
days += d2 - d1;               // 补足天数
复杂度与对比
循环至多 3000 次（年份差）+ 12 次（月份差），仍然足够快；只用 isLeap 和每月天数，不用 cum 表、不用 floor 公式，不容易写错。下一页的换算解法把同样的循环用公式闭合到 \(O(1)\)。

思路

做法把日期换算成天数

不逐日模拟。把每个日期换算成从起点到该日期的总天数，两个整数相减即为答案。
总天数分三段：之前所有整年 + 当年之前的整月 + 当月的天。整年段用公式 \(365(y-1)+\left\lfloor\dfrac{y-1}{4}\right\rfloor-\left\lfloor\dfrac{y-1}{100}\right\rfloor+\left\lfloor\dfrac{y-1}{400}\right\rfloor\)——后三项合起来恰好是 \(1\) 到 \(y-1\) 年之间的闰年个数。
整月段不用循环：非闰年的累计天数表 cum[m] 直接查；当年是闰年且月份超过 2 月，再补 1 天闰日。
闰年判断只写一次，放进 isLeap 函数。
例子：换算 2008-3-1
整年 \(365\times2007+501-20+5=733041\)（后三项合为 486 个闰年），整月查表 \(cum[3]=59\)，当月加 1，闰年且已过 2 月再补 1：合计 \(733041+59+1+1=733102\)。
复杂度
两次换算各只有常数次算术运算和一次查表，是严格的 \(O(1)\)，且代价与两个日期的间隔无关。逐日模拟则要按间隔天数循环，间隔接近 3000 年时要跑约 110 万次，代码更长、更容易错。

代码完整实现

date.cpp 
#include <iostream>
#include <cstdlib>
using namespace std;

bool isLeap(int y) {                   // 闰年规则只写这一次
    return (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
}

// cum[m] = 平年中第 m 月之前的天数；cum[0] 不用
const int cum[13] =
    {0, 0, 31, 59, 90, 120, 151, 181, 212, 243, 273, 304, 334};

// 把 y-m-d 换算成天数；只有差值有意义
int toDays(int y, int m, int d) {
    int y0 = y - 1;                    // 第 1 .. y-1 年都是完整的年份
    int days = 365 * y0 + y0 / 4 - y0 / 100 + y0 / 400;
    days += cum[m];                    // 第 m 月之前的整月
    if (m > 2 && isLeap(y)) days++;     // 第 y 年的闰日已经过去
    return days + d;                   // 当月内的天数
}

int main() {
    int y1, m1, d1, y2, m2, d2;
    cin >> y1 >> m1 >> d1;
    cin >> y2 >> m2 >> d2;
    int diff = toDays(y2, m2, d2) - toDays(y1, m1, d1);
    cout << abs(diff) << endl;
    return 0;
}
要点
  • 闰年规则只写一次（isLeap）
  • (m > 2 && isLeap(y)) 是 bool 运算，0/1 正好补闰日
  • abs（在 <cstdlib> 中）保证答案非负
运行结果
输入  2008 1 1 / 2009 1 1
输出  366

送过去的人不再回来，剩下的局面与原问题结构相同，是同样的子问题，继续迭代。
直到剩余 3 人以内，套不上上面的安排，单独处理边界。
基本送法只有两种
「1」——1 陪 \(a_j\) 过河、1 划回，净送一人，代价 \(a_1 + a_j\)；
「2」——1、2 过河、1 划回，某两人同船过河、2 划回，净送两人，代价 \(a_1 + 2a_2 + (\text{同船较慢者})\)。
计算概论A · 习题课
分析 · 化归

化归只需比较「1+1」与「2」

处理最慢者时，开头的走法只有三种：「1+1」——\(a_m\)、\(a_{m-1}\) 各由送法「1」送走；
「2」——\(a_m\)、\(a_{m-1}\) 由送法「2」同船送走；
「1+2」——先「1」送 \(a_m\)，再「2」送 \(a_{m-1}\)、\(a_{m-2}\)。

「1+2」不优于「2+1」：两者送走同样三人（\(a_m\)、\(a_{m-1}\)、\(a_{m-2}\)），此后同样剩 \(a_1, \dots, a_{m-3}\)、船在左岸，记最优后续为 \(T'\)。代价分别为\[(a_1 + a_m) + (a_1 + 2a_2 + a_{m-1}) + T' \quad\text{与}\quad (a_1 + 2a_2 + a_m) + (a_1 + a_{m-2}) + T',\]相减之差为 \(a_{m-1} - a_{m-2} \ge 0\)。
「2+1」不优于「2」：「2+1」是先走「2」、再以「1」送 \(a_{m-2}\) 并续走 \(T'\)——这整段续走是「2」之后局面的一种合法走法，不优于该局面的最优续走 \(T\)。故「2+1」的总代价 \(\ge\) 「2」\(+\,T\)。
合起来：任何「1+2」开头的方案，总代价都不低于某个「2」开头的方案。
问题化为只需比较「1+1」与「2」——两者送走最慢两人后剩余局面完全相同（剩 \(a_1, \dots, a_{m-2}\)、船在左岸）。
两式相减：\(C_1 - C_2 = (2a_1 + a_{m-1} + a_m) - (a_1 + 2a_2 + a_m) = a_1 + a_{m-1} - 2a_2\)：\(\le 0\) 取「1+1」，否则取「2」。

分析

边界剩余 3 人以内，逐情况推导

剩 3 人（\(a \le b \le c\)）：按两类走法比较。
分别送：1 陪 \(c\) 过河、1 返回（\(c+a\)），此时剩 2 人，直接同船过河（\(b\)），合计 \(a+b+c\)——第二次返回不必要，因为左岸只剩 1 人。
同船送：1、2 过河（\(b\)）、1 返回（\(a\)）、\(b\) 与 \(c\) 同船过河（\(c\)）、2 返回（\(b\)）、最后 1 人过河（\(a\)），合计 \(2a+2b+c\)。因 \(a+b \le 2a+2b\) 恒成立，分别送恒不劣于同船送。
故剩 3 人时必取分别送，合计代价 \(a+b+c\)。
剩 2 人：一起过河，代价 \(b\)。
剩 1 人：直接过河，代价 \(a\)。
迭代结构
每轮按决策规则送走一人或两人，m 相应减 1 或减 2；循环条件 m > 3，退出时只剩 3/2/1 人，各写一个分支。排序 \(O(n\log n)\) 是主要开销，决策循环最多 n 次。

#include <algorithm>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n, a[1001];
        cin >> n;
        for (int i = 1; i <= n; i++) cin >> a[i];
        sort(a + 1, a + n + 1);        // 现在 a[1] 最快

        int total = 0;
        int m = n;                     // 尚未送过去的人数
        while (m > 3) {
            if (a[m - 1] + a[1] > 2 * a[2]) {
                // 送次慢者代价更大：让最慢两人同船
                total += a[m] + a[1] + 2 * a[2];
                m -= 2;
            } else {
                // 最快者陪最慢者过河，再独自划回
                total += a[m] + a[1];
                m -= 1;
            }
        }
        if (m == 3)      total += a[1] + a[2] + a[3];
        else if (m == 2) total += a[2];
        else             total += a[1];
        cout << total << endl;
    }
    return 0;
}

DP状态与转移

排序后记 \(f[i]\)：前 \(i\) 快的人全部过河、船停在右岸的最短时间。边界 \(f[1]=a_1\)，\(f[2]=a_2\)，\(f[3]=a_1+a_2+a_3\)，递推自 \(i=4\) 起（见「边界」页）。

转移只须考察「\(i\) 最终过河的那次航行」：由化归，只有两种送法——1 陪同单独送，或与 \(i-1\) 同船（「1+2」已排除）。
1 陪 \(i\) 过河：先让前 \(i-1\) 人过河（\(f[i-1]\)，船在右岸），1 划回（\(a_1\)），陪 \(i\) 过河（\(a_i\)）。候选一：\(f[i-1] + a_1 + a_i\)
\(i-1\) 与 \(i\) 同船过河：先让前 \(i-2\) 人过河（\(f[i-2]\)），1 划回（\(a_1\)），\(i-1\) 与 \(i\) 同船过河（\(a_i\)），2 划回接 1、再同船过河（\(2a_2\)）。候选二：\(f[i-2] + a_1 + 2a_2 + a_i\)。
两种候选的剩余局面都是同结构的子问题，最优子结构成立（每步取哪个由数据决定，不必事先推出比较规则）：\[f[i] = \min\big(f[i-1] + a_1 + a_i,\ f[i-2] + a_1 + 2a_2 + a_i\big).\]
DP 的一般思路
定状态：找到唯一决定后续局面的量（这里 \(f[i]\) 还隐含「船在右岸」）；找转移：只看最后一步，化为更小的同结构子问题；定边界：最小局面直接给出；递推：从小到大填表，答案取 \(f[n]\)。

第 5 题 炸鸡排

题目描述　小P买了n块鸡排，想将它们做成美味的炸鸡排，其中第i块鸡排需要t[i]秒炸熟。小P只有一个炸锅，炸锅内可以放置k(k≤n)块鸡排。小P是个完美主义者，他要求任意时刻炸锅内必须恰有k块鸡排。他可以在任意时刻改变锅内正在炸的鸡排，只需保证已经熟了的鸡排不能继续留在锅中。小P希望知道炸鸡排最多可以持续多少时间。

例如，小P的三块鸡排需要分别需要1,1,1的时间炸熟，炸锅内需要放置2块鸡排，那么他决定在第一个0.5秒炸1和2两块鸡排，第二个0.5秒炸2和3两块鸡排，第三个0.5秒炸1和3两块鸡排，共持续了1.5秒。

关于输入　第一行输入两个正整数n和k，k≤n。第二行输入n个正整数，代表n块鸡排分别需要炸熟的时间t[1],t[2]...t[n]。输入数据保证，n≤1000，0＜t[i]≤1000000。

关于输出　输出一个双精度浮点数，代表炸鸡排最多可以持续的时间，结果保留三位小数。

例子输入
4 2
5 1 1 2
例子输出
4.000
怎么炸（共 4 秒）
0-1 秒：炸 5 和 1（1 熟）
1-2 秒：炸 5 和 1（1 熟）
2-4 秒：炸 5 和 2（2 熟）
5 的那块只炸 4 秒，不必熟
注意审题：目标是持续最久，不是全部炸熟！
计算概论A · 习题课
解法一 · 模拟

思路按题意直接模拟炸的过程

锅内始终放「剩余炸制时间最长」的 \(k\) 块——直译题意，就是反复取当前最慢的 \(k\) 块下锅，熟一块换一块。
关键：边界处若有并列（剩余时间相同），锅位要在它们之间轮流、它们同时出锅——必须作为一个整体（并列段）来算。
排序后，锅里固定是最慢的 \(k\) 块；锅位边界 \(B=n-k+1\) 若切在一组剩余时间相同的鸡排中间（\(t[l]=\cdots=t[r]\)，\(l\le B\le r\)），称 \([l,r]\) 为并列段：大小 \(sz=r-l+1\)，其中在锅里 \(p=r-B+1\) 块、锅外等待 \(w=sz-p\) 块。
锅位在段内轮流换，段里每块只按 \(p/sz\) 变熟。下一步只有四种：段追平 \(t[l-1]\)（汇合）、\(t[r+1]\) 追平段（拉平）、段整体炸熟、右边更慢者先熟——各算时间，取最先发生。
用样例走一遍（4 2 / 5 1 1 2）：初始排序 [1,1,2,5]，B=3，锅里是 {2,5}，边界块 2 无并列，段=[3,3]，p=1。
事件时间：汇合 \((2-1)\cdot 1/1=1\)；拉平 \(\infty\)；段熟 2；右块熟 5 → 汇合先发生，执行 1 秒。
t=1：状态变 [1,1,1,4]（2 烧成 1、5 烧成 4），段=[1,3]（三个 1），p=1、sz=3。
事件时间：汇合 \((1-0)\cdot 3=3\)；拉平 \((4-1)\cdot 3/2=4.5\)；段熟 3；右块熟 4 → 段熟先发生，执行 3 秒：三个 1 全熟出锅，剩 n=1<k=2，结束。
ans = \(2\times1+2\times3=8\) 锅·秒 → \(8/2=4.000\) ✓。对应时间表 [0,1] 炸 {2,5}，[1,4] 炸 {4, 三个 1 轮流}（第 25 页「怎么炸」是另一种合法方案）。
有鸡排出锅就将其移出序列；若某次出锅后未熟的鸡排不足 \(k\) 块，过程立即结束。ans 按「锅·秒」累计，除以 \(k\) 即持续时间。

解法一 · 模拟

代码按题意模拟的完整实现

sim.cpp 
#include <iostream>
#include <algorithm>
#include <iomanip>
using namespace std;

int n, k;
long double t[2001];   // 排序后的剩余时间；t[0] 恒为 0，用作哨兵
long double ans;       // 累计锅位占用（单位：鸡排·秒）

int main() {
    cin >> n >> k;
    for (int i = 1; i <= n; i++) cin >> t[i];
    sort(t + 1, t + n + 1);
    if (n == k) {                    // 全部都能下锅：最快的一块炸熟即结束
        cout << fixed << setprecision(3) << t[1] << endl;
        return 0;
    }

    const long double INF = 1e30L;
    int l = n - k + 1, r = n - k + 1;  // [l, r]：锅位边界上的并列段
    while (l > 0 && t[l] == t[l - 1]) l--;
    while (r < n && t[r] == t[r + 1]) r++;

    while (true) {
        int B = n - k + 1;                 // 最左边的锅位
        int sz = r - l + 1;                // 并列段大小
        int p = r - (l > B ? l : B) + 1;   // 并列段中当前在锅里的块数
        int w = sz - p;                    // 并列段中在锅外等待的块数
        long double b = t[r];              // 并列段共同的剩余时间

        // 从当前状态到四个候选事件所需的时间
        long double dMerge = (B >= l) ? (b - t[l - 1]) * sz / p : INF;
        long double dLevel = (r < n && w > 0) ? (t[r + 1] - b) * sz / w : INF;
        long double dBlock = b * sz / p;   // 并列段整体炸熟
        long double dDone  = (r < n) ? t[r + 1] : INF;
        if (B < l) dDone = min(dDone, t[B]);  // 更快的鸡排进了锅

        long double dt = min(min(dMerge, dLevel), min(dBlock, dDone));

        if (dt >= dBlock || dt >= dDone) {
            // 有鸡排先熟：先炸 dt，再移出所有已熟的鸡排
            ans += (long double)k * dt;
            for (int i = l; i <= r; i++) t[i] -= dt * p / sz;  // 炸制时间在段内均匀分摊
            for (int i = r + 1; i <= n; i++) t[i] -= dt;
            for (int i = B; i < l; i++) t[i] -= dt;            // 锅里更快的鸡排
            int m = 0;
            for (int i = 1; i <= n; i++) {
                if (t[i] <= 1e-12L) { m++; continue; }         // 已熟：出锅
                t[i - m] = t[i];
            }
            n -= m;
            if (n < k) break;              // 锅已装不满：过程结束
            l = r = n - k + 1;             // 在新边界上重建并列段
        } else if (dt >= dLevel) {
            // 并列段先与 t[r+1] 拉平：向右扩展
            ans += (long double)k * dt;
            for (int i = l; i <= r; i++) t[i] -= dt * p / sz;
            for (int i = r + 1; i <= n; i++) t[i] -= dt;
            r++;
        } else {
            // 并列段先与 t[l-1] 汇合
            ans += (long double)k * dt;
            for (int i = l; i <= r; i++) t[i] -= dt * p / sz;
            for (int i = r + 1; i <= n; i++) t[i] -= dt;
            l--;
        }
        while (l > 0 && t[l] == t[l - 1]) l--;
        while (r < n && t[r] == t[r + 1]) r++;
    }
    cout << fixed << setprecision(3) << ans / k << endl;
    return 0;
}
要点
  • 并列段 \([l, r]\) 与锅位边界 \(B = n-k+1\)：段内 \(p\) 块入锅、\(w\) 块等待，油时按 p/(r-l+1) 的速率平分
  • 每步取最先事件：汇合 dMerge、拉平 dLevel、并列段熟 dBlock、慢块熟 dDone
  • 出锅后把炸熟的移出序列；不足 \(k\) 块则结束，否则令 l = r = B 重建并列段
  • n == k 时全部下锅，最快的熟了就结束

解法二 · 观察
\(T\)：拟持续的时长（\(T'\) 为任意候选）
\(t_i\)：第 \(i\) 块鸡排炸熟所需时间
\(k\)：锅位数（锅内恒定鸡排数）
\(n\)：鸡排总数

可行条件持续 \(T\) 秒意味着什么

总占用：任意时刻锅中恰有 \(k\) 块，持续 \(T\) 秒就需要恰好 \(kT\) 个「鸡排·秒」。
总供给：第 \(i\) 块鸡排至多贡献 \(\min(t_i,\,T)\) 秒：炸满 \(t_i\) 必须出锅，\(T\) 秒内在锅里至多待 \(T\) 秒。
所以 \(T\) 可行，当且仅当 \(\displaystyle\sum_{i=1}^{n}\min(t_i,\,T)\ \ge\ kT\)：总供给要撑得起总占用。
样例验证（n = 4，k = 2，t = 5 1 1 2）
\(T=4\)：\(\min(t_i,4)\) 之和 \(= 4+1+1+2 = 8 \ge 2\times4 = 8\)，可行；
\(T=4.5\)：\(\min(t_i,4.5)\) 之和 \(= 4.5+1+1+2 = 8.5 \lt 9\)，不可行。最大持续时间就是 \(4\)。

解法二 · 算法
\(t\)：每块鸡排炸熟所需时间（升序）
\(s\)：当前鸡排时间总和 \(\sum t\)
\(k\)：当前锅位数（随删除递减）
\(n\)：当前剩余鸡排数
\(\bar t\)：平均占用 \(s/k\)
\(T^{*}\)：答案，最长持续时间

做法去掉拖后腿的

把 \(t\) 升序排序，记当前平均占用为 \(\bar{t}=\dfrac{\sum_i t_i}{k}\)，考察最大者 \(t_n\)：

若 \(t_n > \bar{t}\)：这块鸡排即使最优也炸不熟，只能全程占住一个锅位——把它连同它的一个锅位一起去掉，答案不变。
若 \(t_n \le \bar{t}\)：所有鸡排都能在最优时长内「用得完」，答案就是 \(\bar{t}\)。
删除会改变平均值，所以循环判断：只要 \(t_n > \dfrac{\sum}{k}\) 就继续删，直到条件不成立。
结论
循环结束时剩余 \(n'\) 块、总和 \(s'\)，答案是 \(T^{*}=\dfrac{s'}{k'}\)。正确性归结为后面两页证明的一个引理。

设 \(k \le n\)，每块 \(t_i \le T=\dfrac{s}{k}\)（\(s=\sum_i t_i\)）。上界显然：持续 \(T'\) 秒需要 \(kT'\) 个「锅·秒」，全部鸡排至多提供 \(\sum_i \min(t_i,T')\) 个，故 \(T'=\dfrac{s}{k}\) 已到顶；下面只证可行性——这些鸡排真的能在 \(T\) 秒内全部炸完。

鸡排任意排成一列、首尾相接铺在数轴上，恰好占满 \([0,s)\)：鸡排 \(i\) 占 \([c_i,\,c_i+t_i)\)（\(t_i\) 秒允许拆成几段完成）。
对折：由 \(s=kT\) 按长度 \(T\) 切成 \(k\) 段，第 \(j\) 段折作锅位 \(j\)，时刻 \(\tau\) 炸「线位置 \(jT+\tau\)」处的那一块。
于是 \([0,T]\) 内每时刻每锅位各炸一块、共 \(k\) 块；合法性见下一页验证。

验证构造的方案满足题设的三个要求

① 任意时刻恰有 \(k\) 块：对应 \((j,\tau)\mapsto jT+\tau\) 是 \([0,kT)\) 的一一表示，故每时刻每锅位恰好一块，共 \(k\) 块。
② 每块恰好炸满 \(t_i\) 秒：鸡排 \(i\) 在锅中的时刻恰是扫过 \([c_i,\,c_i+t_i)\) 的时刻，总长 \(=t_i\)——没扫完不会提前出锅，扫完不再出现。
③ 同一块不同时占两个锅位：因 \(t_i\le T\)，区间至多跨一条折痕。跨折痕时两段时刻是 \([0,\tau_1)\)、\([\tau_2,T)\)，而 \(\tau_1\le\tau_2\iff t_i\le T\)——正是前提，两段不重叠。反之 \(t_i>T\) 时同一块会同时占两个锅位，非法：条件 \(t_i\le T\) 不可少。
结论
引理成立：\(t_i \le \dfrac{s}{k}\) 时可恰好持续 \(\dfrac{s}{k}\) 秒。循环删除后剩余鸡排对剩余锅位 \(k'\) 满足引理条件，故 \(T^{*}=\dfrac{s'}{k'}\) 可达；又不超过上界，故最优。

#include <iostream>
#include <iomanip>
#include <algorithm>
using namespace std;

// 贪心：反复删掉「超过平均占用 sum/k」的最大块（连同它的锅位）
// 删完后剩余鸡排都能在 sum/k 秒内用完（引理），答案 = 剩余总和 ÷ 剩余锅位
int main() {
    int n, k;
    cin >> n >> k;
    int t[1005];
    for (int i = 1; i <= n; i++) cin >> t[i];
    sort(t + 1, t + n + 1);            // 升序排序：t[n] 是当前最大的一块

    double sum = 0;                    // 当前所有鸡排的时间总和
    for (int i = 1; i <= n; i++) sum += t[i];
    while (n > 1 && t[n] * k > sum) {
        // t[n]*k > sum 即 t[n] > sum/k：最大块超过平均占用，永远炸不熟
        //（乘法比较避免浮点除法；n > 1 保证至少留一块，不会删空）
        sum -= t[n];                   // 把它从总和里去掉
        n--;  k--;                     // 连同一个锅位一起删掉
    }
    cout << fixed << setprecision(3) << sum / k << endl;   // 答案 = 剩余总和 ÷ 剩余锅位
    return 0;
}
要点
  • 循环不变量：答案恒等于当前剩余集合的 \(\sum t_i \big/ k\)
  • t[n] * k > sum 即 \(t_n\) 与平均值比较（乘积 \(\le 10^9\)，int 安全）；sum 用 double 保证除法精度
