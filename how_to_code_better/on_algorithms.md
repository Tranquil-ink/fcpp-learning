# 时间复杂度估计
- 在有做题思路之后、正式开始写代码之前先验证时间复杂度是否符合要求，不然会白白浪费时间
- 时间复杂度上限一般不超过10的9次方这个数量级，少数题目会卡常数，计概考试一般不会出现，所以不做考虑
- 注意O(nlogn)几乎非常接近O(n)了，从O(n^2)到O(nlogn)是非常好的优化，二分往往在这种优化上有奇效
- 另外，预期时间复杂度甚至能引导我们解题
*输入范围在十万，就绝不能用O(N2)算法；但如果只有1000，完全可以*



| 数据规模 | 通常可以承受的复杂度 | 本套题中的例子 |
| --- | --- | --- |
| $n \le 2000$ | $O(n^2 \log n)$ | T6（$n \le 1000$） |
| $n \le 5000$ | $O(n^2)$（常数不大） | —— |
| $n \le 10^5$ | $O(n\sqrt{n})$ 或 $O(n\log n)$ | T4 |
| $n \le 10^6$ | $O(n\log n)$（常数一般即可） | T8（$N \le 10^6$，$O(n)$） |
| $n \le 10^7$ | $O(n)$，常数比较小 | —— |

### 估计数量级

评测机每秒约 $10^8 \sim 2 \times 10^8$ 次简单运算，只要算出来低于这个范围就基本能够通过，考试试题不会为难复杂度正确的做法。

$10^6$ 个元素的排序约 0.1 秒；$5000^2$ 的二重循环只要内层不是特别复杂也能通过。

## 复杂度看似正确？


### 1. 在for循环种重复调用某个函数
典型的是 `strlen(s)` 求一个 `char` 数组的长度，其复杂度为 $O(n)$。

于是 `for (int i = 0; i < strlen(s); ++i)` 是 $O(n^2)$，正确的做法应该先用 `int len = strlen(s);` 保存长度。

### 2. 函数参数按值传递 vector

函数参数按值传递 `vector`，如 `void f(vector<int> a)`，这样每次调用都复制一遍；正确的做法是 `void f(vector<int> &a)`。

### 3. 输入输出问题

用 `cin` 读入太多整数，输入 $10^6$ 级别的时候会比较慢。

用 `endl` 进行换行，这样每行都刷新缓冲。改成 `'\n'` 会使得输出变快。

`std::ios::sync_with_stdio(false);` 能够使得 `cin` 变快。（但是代价是什么呢？）

### 4. 循环问题

`while (x > 0)` 里忘了 `x /= 10`，或者循环变量在循环体里被改掉。

## 魔王军队
*画图找思路*
每次从当前尚未覆盖的最左边元素开始，找到其右边R以内最后一个元素，把石头放在这
*把思路转化成代码*
变量要有明确的物理意义； 
**边界情况处理技巧：循环中使i = v.size()作为越界判断，但要保证这个i不会被访问**

```cpp
int countstone(vector<int> &v, int r){
    int i = 0;  //首个还没覆盖的士兵
    int j = 0;  // 扫描的指针
    int p; // 放石头的位置
    int stonecount = 0;
    int n = v.size();

    while(i<n){
        while(j<n&&(v[j]-v[i])<=r){  //注意判断顺序不能反！！否则数组越界访问
            j++;
        }
        p=j-1;
        stonecount++;

        j = p+1;
        while(j<n&&(v[j]-v[p])<=r){
            j++;
        }
        i = j;
    }
    return stonecount;
}
```
